# CLAUDE.md — 오행 친구들 / Hanji Fortune Fables

이 파일은 **Claude Code가 기존 Lovable 소스코드를 인수인계하여 개발하는 경우의 프로젝트 지침**이다. 사용자 승인·실제 소스·타입/테스트 증거보다 추정이 우선하지 않는다. 최초 실행 시 `PROJECT_HANDOFF.md`, `AI_EXPERT_HYBRID.md`, `MIGRATION_AND_QA.md`, `handoff/reference_specs/OHENG_R001_R015_RESTORED_MASTER.md`, `handoff/reference_specs/오행친구들_PRD_v1.0.md`, 그리고 기존 앱의 `AGENTS.md`, `roadmap.md`, `docs/`, `src/`, `package.json`을 읽어라.

## 최우선 절대 규칙
1. **프로젝트 재작성 금지**: 기존 코드를 우선 보존·분석. 기존 디자인/라우트/기능/테스트를 임의 삭제하거나 새 프로젝트로 덮어쓰지 말 것.
2. **운영 DB 무단 변경 금지**: 사전 승인 없이 DDL/DML, GRANT/REVOKE, 테이블 drop, production DB migration, 진짜 회원/냥·원장 변경, 결제/보상 활성화, 운영 배포/도메인·공개 상태 변경하지 말 것.
3. **비밀값 엄수**: `.env`/service_role/GPT/Gemini/PG 키/회원정보를 클라이언트, 로그, Git, 프롬프트에 유출 금지. `.env.example`은 키 이름만. 실사용자 데이터를 AI에 보내기 전에 개인정보 동의·정책 검토.
4. **승인 표시 보존**: `finalApproved=false`, R015 `NO_GO`, 유료 상품 `active=false`가 기본. 테스트 PASS ≠ 명리/보안/결제/출시 승인.
5. **자료 진실성**: `R-002~R-009`의 세부 원문이 일부 미확보다. 요약복원/코드 참조를 원문 확보 또는 명리 전문가 승인으로 오인하지 말 것. `R006/009/010/011/013` 및 120개 조후 항목은 추가 검증 전 확정 발행 금지.
6. **사주 결정론 엔진 우선**: LLM이 생년월일/간지/일주/월주/십성/월령/합충/대운/세운/격국/용신의 근거 사실을 임의 생성·수정하거나 전통적 해석을 과학적 예측으로 포장해서는 안 된다.
7. **서비스 분리**: 개발용 Staging Supabase와 실제 운영 Supabase를 명시적으로 구분하고, staging 전용 가드로 생산 접속 차단. 미검증 프록시 헤더를 신뢰하지 않는다. 운영은 영속 rate RPC 실패 시 fail-closed.
8. **영향이 큰 작업 전에** ①현재 상태 스냅샷 ②변경 대상 ③위험 ④자동/수동 검증 기준 ⑤롤백 방법을 제시. 문서·코드·데이터·배포는 각각 다른 승인 단위.
9. **Lovable Git 동기화 주의**: 프로젝트 기존 `AGENTS.md`의 연결 브랜치 금지 규칙을 준수. 실사용 브랜치 force push, 이미 공유된 이력 rebase/amend 금지.

## 핵심 목적
- 한국어 20~40대 여성 중심의 모바일 웹 사주 서비스 **오행 친구들**.
- 독창적인 한지·민화·조선풍 10일간 캐릭터(甲乙丙丁戊己庚辛壬癸), 무료 캐릭터/오늘의 운세 → 공유/추천 → 로그인 → 유료 콘텐츠.
- P0 현금/냥: 기본사주 990원/4냥, 궁합 990원/4냥, 심층 연애운 3900원/12냥. P1 비활성: 택일 4900원/15냥, 심층사주 5900원/18냥.
- 추천 신규 사용자: 무료 캐릭터 체험 완료 + 유효 신규 회원 가입 검증 시 추천인 2냥; 1일 5건/월 30건 한도. 중복·자기추천 방지/원장 멱등 필수.
- 심층 연애운 5년은 **조회 시점의 역년 포함 연속 5개 역년** (2026 조회 → 2026~2030). 궁합/상대방 정보·결과는 30일 정책(구체 파기/백업 처리 검토). 유료 다른 리포트는 계정 유지 기간 재열람, 탈퇴/삭제 요구 시 파기 설계.
- 비회원 체험 → 결제 직전 카카오/구글/이메일 간편 로그인. 공유카드에 출생정보·결제정보 노출 금지.

## 주요 기술·작업 방식
- **현재 앱**: React, TypeScript, TanStack Start/Router, Supabase/Lovable Cloud, Bun 락파일, Vitest, `astronomy-engine`, `korean-lunar-calendar`, 서버 전용 계산/전환.
- 본 프로젝트는 Lovable에서 Git으로 이관할 **실제 앱 저장소**가 단일 기준이다. 동봉 R001~015 참고 코드·예전 패키지는 다른 연구 단계 산출물로, 실사용 앱에 자동 교체/병합하지 않는다.
- `src/lib/saju-engine.server.ts`: 사주 원국; `src/lib/lunar-conversion.server.ts`: 음력→양력; `src/lib/user-fns.ts`: 본인 데이터, 지갑; `src/lib/rate-limit.server.ts`, `src/lib/saju-fns.ts`: R015 제한; `src/start.ts`: 인증 미들웨어. 실제 코드와 충돌하면 소스·테스트로 근거를 남겨 리뷰.
- `src/integrations/supabase/client.server.ts`는 서버 전용, 절대로 클라이언트 번들에 서비스키 포함 금지. user-fns/auth middleware/RLS/SECURITY DEFINER 경로 보존.

## 명리 해석 엔진 R001~015
- `R001`: 만세력 정확성·절입/법정시/음력 원본 보존. 현재 앱 구현 범위와 참조 규격의 목표 범위 불일치 가능.
- `R002`: 월령 계절 세력(득령 ≠ 최종 신강 판정).
- `R003`: 지장간 고정표와 사령 분일; 출처/시각/버전 분리.
- `R004`: 통근·득지·진정한 근의 강약/충합 영향.
- `R005`: 천간 생극설·소모/6쌍·천간합과 구조 후보(DRAFT-2).
- `R006`: 신강·신약·중화 후보; 득령·통근·천간 증거·반증, 특수격 검토 후 제한 재평가.
- `R007`: 월령 및 투출에 근거한 격국 후보, 최종 격국 임의 확정 금지.
- `R008`: 동일천간 투출/동오행 노출/합화 분리, 잡기·회합 후보.
- `R009`: 건록·월겁·양인·종격·가종격 후보 및 유보.
- `R010`: 격국 성패·파격·구응·겸격, 미검증 시 review_required.
- `R011`: 격국용신·상신 후보와 파상신/구응 근거 추적.
- `R012`: 억부용신 후보; 단일 최종 확정 금지.
- `R013`: 조후·통관·병약 후보; 10일간×12월령 120개 색인 대부분 원전 교감 대기.
- `R014`: 격국/억부/조후/통관/병약 교차 판단, 충돌·유보, 단일 용신 강제 지정 금지.
- `R015`: G0~G6, claim 단계별 승인, `NO_GO / LIMITED_GO / GO`; 자동 테스트는 운영 승인 대체 불가.

## AI 전문가 하이브리드(B안)
- 결정론적 만세력/명리 근거엔진(승인된 claim만 제공) → GPT 한국어 상담 리포트 작성 → Gemini **별도 독립 비판 검토** → 구조적 검증/재작성 제한 → 근거와 버전 저장.
- GPT/Gemini 어떤 모델도 원국/미승인 격국·용신을 **결정할 권한이 없음**. 교차검증 불일치 시 `REVIEW`, 심각 불일치·근거 없음 시 `BLOCK`; 모델 합의가 사실 정확성 보증은 아님.
- 과도한 단정/공포·차별·의료·투자·임신·법률 관련 인생 결정을 유도하는 문구 금지. 과거/미래 사건 발생을 검증된 확률로 제시하지 않는다.

## 코드 분석 후 출력 형식
1. **현재 실제 상태**: 완료/부분구현/미구현/위험/확인불가를 경로·테스트로 구분.
2. **문서 충돌표**: 제품 PRD vs R001~15 복원 vs 앱 소스 vs DB 실제 스키마.
3. **P0/출시 게이트/보안 위험 정리**: 긴급, 다음 단계, 보류.
4. **하나씩 작업**: 작업 전 변경 계획을 제시하고, 테스트/빌드/타입검사 및 보안 검사 결과로 확인. 다음 단계 이전의 미승인 기능/운영 변경 금지.

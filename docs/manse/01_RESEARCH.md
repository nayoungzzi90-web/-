# 1. 자료·라이선스 조사 보고서 (만세력 엔진)

작성 환경: 격리된 클라우드 컨테이너. **외부 접속이 허용된 호스트만 열려 있어, 한국천문연구원(KASI)·공공데이터포털·JPL·Astrodienst 웹사이트는 모두 연결에 실패했다**(`curl` 응답 코드 000, 2026-10-15 시도).
이 보고서는 "실제로 열어서 확인한 것"과 "확인하지 못한 것"을 분리해 적는다. 확인하지 못한 항목은 추정으로 채우지 않았고, 배포 전 사람이 확인할 체크리스트로 남겼다.

## 1.1 한국천문연구원(KASI) 공식 자료 — ❌ 이 환경에서 확인 불가

| 확인하려던 항목 | 상태 | 비고 |
|---|---|---|
| 월력요항 제공 연도 범위 | **확인 못함** | `www.kasi.re.kr`, `astro.kasa.re.kr` 접속 실패 |
| 절입시각 정밀도(분/초) | **확인 못함** | 분 단위일 가능성이 있으나 문서로 확인하지 못해 가정하지 않는다 |
| 공공데이터 API(특일/24절기/음양력) 응답 필드 | **확인 못함** | `www.data.go.kr` 접속 실패 |
| 상업적 이용 조건(공공누리 유형 등) | **확인 못함** | 약관 원문 미확인 |

→ 엔진은 공식값 없이도 동작하지만, 그때 결과는 **"천문 계산값(공식 미확인)"** 으로만 표시된다. 공식값을 가져오면 `official_solar_terms` 에 적재하고 비교 도구가 상태를 올린다(§3, 검증 문서).
→ **사람이 직접 확인할 일**: (1) 월력요항 PDF 의 제공 연도·절입시각 표기 단위, (2) 공공데이터 API 활용신청 후 응답 필드·호출 제한·이용허락범위 약관(상업 이용 가능 여부), (3) 출처 표시 의무.

## 1.2 Astronomy Engine (npm `astronomy-engine`) — ✅ 확인

- 버전 2.1.19, 라이선스 **MIT** (저장소 LICENSE 원문 확인, `Copyright (c) 2019-2025 Don Cross`). 상업 이용 가능, 저작권 고지 유지 조건.
- 문서의 정확도 주장: "accurate to within ±1 arcminute", NOVAS 대비 1 arcminute 이내.
  - **주의**: 태양 황경 1′ 은 시간으로 약 **24분**(태양은 하루 약 0.9856° 이동). 이는 상한 보증일 뿐 실제 오차는 아니다.
- ΔT: 내장 Espenak–Meeus 다항식(`DeltaT_EspenakMeeus`), 교체 함수 제공.
- **실측(본 프로젝트)**: 1900–2050 의 24절기 3,624건을 DE421 기준값(§1.4)과 TT 기준으로 비교 → **최대 56.1초, p99 38초**(2051–2100: 최대 46.4초). 분 단위 경계를 확정하기에는 부족하다.
  → Astronomy Engine 은 **기준값 생성기로 쓰지 않고**, 대략 검산(런타임 sanity check)과 개발 도구로만 쓴다.

## 1.3 Swiss Ephemeris — ✅ 라이선스 원문 확인

`aloistr/swisseph` 저장소 LICENSE 원문(확인함): **이중 라이선스** — (a) GNU AGPL, (b) Swiss Ephemeris Professional License.
- 개발자는 "소프트웨어를 남에게 배포하기 전, 그리고 이를 사용한 **공개 서비스를 시작하기 전에**" 둘 중 하나를 선택해야 한다.
- AGPL 선택 시 **프로젝트 전체를 AGPL 또는 호환 라이선스로 공개**해야 한다. Professional 은 Astrodienst 에서 구매·계약해야 한다(가격은 확인 못함).
- **결론**: 상용 웹서비스의 런타임/배포물에는 포함하지 않는다. 오프라인 **교차검증 도구**로만 사용(Moshier 모드, 데이터 파일 불필요)하며, 그 코드·데이터를 저장소에 넣지 않는다. 검증 결과의 수치(차이값)만 기록한다.
  - 법적 판단은 변호사/Astrodienst 확인이 필요하다. 이 판단은 라이선스 원문 읽기에 근거한 개발자의 보수적 선택이며 법률 자문이 아니다.

## 1.4 독립 기준값: JPL DE421 (파이썬 `de421` 2008.1 + `jplephem`)

- `de421` 패키지(MIT, jplephem 저장소)에 NASA/JPL DE421 의 Chebyshev 계수가 들어 있고, `jplephem 2.6` 으로 읽는다(둘 다 PyPI 에서 설치됨).
- 패키지가 알려주는 JD 범위: 2414992.5 – 2524624.5 (**1899-07-29 – 2200-02-20**). JPL 의 공식 DE421 범위 문서는 접속 불가로 확인하지 못했다. 2053년 이후 구간은 **Swiss Moshier 와 직접 대조**했다(아래).
- 본 프로젝트의 환산 과정(`tools/ref/de421_events.py`): 광시간 반복 보정 → 상대론적 광행차 → IAU 2006 세차 → IAU 2000B 장동(Δψ) → 날짜 기준 진황도 황경. 외부 천문 서비스 호출 없음.
- **독립 검증 결과**(TT 기준, 시간 척도 오차 제거): DE421 환산 vs Swiss Ephemeris(Moshier) — 1900–2050 **최대 2.01초**(n=3,624), 2051–2100 **최대 2.25초**(n=1,200). 서로 다른 구현·다른 이론 기반이므로 두 값이 2초 안에서 일치한다는 점이 환산 절차의 신뢰 근거다. (`data/verification_summary.json`)
- 한계: 두 값 모두 "천문학적 정의의 절입 순간"이고, KASI 공식표와의 일치는 **미확인**이다.

| 항목 | 출처 | 상태 |
|---|---|---|
| ΔT (TT−UT) | skyfield 내장 표(IERS+Morrison/Stephenson 계열), swisseph 와 1900–1970 에서 ≤0.8초 일치. Astronomy Engine(Espenak–Meeus)과는 최대 ~1초 차이 | 확인(수치 비교) |

## 1.7 조사 결론

1. **천문 절입 순간은 신뢰 가능한 수준(±2초)으로 계산·교차검증했다.** 그러나 **KASI 공식값과의 일치는 확인하지 못했으므로** 모든 절기 행의 상태는 `cross_checked`(독립 천문 계산 2종 일치)까지만 올라가고 `official_confirmed` 는 0건이다.
2. 서비스 런타임은 라이선스가 명확한 **사전 계산 DB/JSON 표**를 읽는다. 런타임에 외부 천문 라이브러리를 쓰지 않는다.
3. 2051–2100 구간은 DE421 패키지 범위 안이지만 JPL 공식 범위 밖일 수 있고, ΔT·윤초가 예측값이므로 `uncertainty_seconds` 를 더 크게 둔다.
4. 상업 이용 조건(KASI 자료 이용허락, 공공데이터 약관)은 **법적 확인 항목으로 남아 있다.**

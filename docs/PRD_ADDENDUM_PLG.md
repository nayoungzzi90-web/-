# PRD 부록: 경쟁사 벤치마킹 및 Product-Led Growth 전략

> 출처: 사업기획 검토 자료(사용자 제공). 사주아이의 실적 수치(누적 사용자 165만 명 이상, 누적 매출 50억 원 이상, 2025-09 출시)는 **창업자 공개 자료상의 주장**이며 독립적으로 검증된 재무정보가 아니다. 이 저장소에서 확인하지 못했다.

## 1. 핵심 결론
사주아이를 가격으로 따라가지 않는다. **공유하고 싶어지는 무료 경험**과 **구매하고 싶어지는 유료 경험**을 분리해 설계한다. 경쟁력은 (1) 조선 민화풍 캐릭터 세계관, (2) 전문가 검수 기반 해석 품질, (3) 친구에게 공유하고 싶은 무료 경험의 결합이다.

## 2. 이번 개정에서 확정한 결정 (제품 책임자 답변)

|---|---|---|---|

| 추천 보상 | 2냥(2닢) | **엽전 1닢 유지** | 일 5명·월 30명(KST) 상한 유지, 지표를 본 뒤 상향 검토 |

## 3. 우선순위와 구현 현황
| 우선순위 | 과제 | 측정 지표 | 구현 |
|---|---|---|---|
| P0 | 무료 캐릭터 10종의 매력 검증 | 결과 완료율, 공유율 | 홈 빠른 시작 → 결과, 결과 상단 공유 버튼 |
| P0 | 회원가입 없는 무료 체험 | 진입→결과 완료율 | 게스트 체험 유지, 홈에서 한 화면 입력 |
| P0 | 900원 기본사주·궁합 결제 | 결과→첫 구매 전환율 | 결과 화면 추천 상품(고민 범주 연동) |
| P0 | 추천 링크와 엽전 지급 | 유효 추천 가입 수, 부정 보상률 | 기존 상태머신 + 지표 화면 |
| P0 | 만세력·AI 리포트 검수 | 계산 오류율, 생성 실패율 | 이벤트 `calc_error`·`report_failed` 집계 |
| P1 | 심층 연애운 업셀링 | 첫 구매→추가 구매 전환율 | 리포트 말미 추천(연애 고민→연애운, 관계 고민→궁합) |
| P1 | 오늘의 운세 재방문 | 7일·30일 재방문율 | 연속 출석 도장판, 홈 연속일수 |
| P1 | 스레드·인스타 콘텐츠 실험 | 콘텐츠별 유효 방문·가입 | 공유 링크 `?ref` 귀속(콘텐츠 채널 태깅은 후속) |
| P2 | 택일·심층사주 | 상품별 공헌이익·재구매율 | 준비 중 |

## 4. 성장 퍼널
SNS 콘텐츠 발견 → 무료 사주 캐릭터(10종 + 성향별 변형) → 친구 초대(검증된 가입 시 엽전 1닢) → 900원 첫 구매(기본사주·궁합) → 심층 연애운 → 오늘의 운세 재방문.
핵심 KPI는 조회수가 아니라 **신규 방문자당 매출, 유효 추천 가입률, 고객당 공헌이익**.

## 5. 수익성 시뮬레이션 (가정 기반)
기본 가정: 월 방문 100,000 · 무료 결과 완료 60% · 구매 전환 8% · 주문당 2,500원 → 완료 60,000 · 주문 4,800 · 매출(비용 차감 전) 12,000,000원.
**실제 순이익은 PG 수수료·AI·인프라·엽전·환불·세금을 차감해야 계산된다.** `운영 지표 > 수익성 시뮬레이터`에서 가정을 바꿔 공헌이익·세전 이익·목표 달성 필요 방문자 수를 볼 수 있다(수치는 사주아이의 실제 전환율이 아니라 검토용 변수).

## 6. 사업계획서 문안
> 오행 친구들은 사주아이의 저가 진입 전략과 바이럴 성장 구조에서 사업적 시사점을 얻되, 조선시대 민화풍 캐릭터 세계관과 전문가 검수 기반 AI 명리학 해석으로 차별화한다.
1. 무료 사주 캐릭터로 신규 고객을 확보하고, 캐릭터 이미지·개인별 칭호로 SNS 공유를 유도한다.
2. 회원가입 없이 무료 체험을 제공해 초기 장벽을 낮춘다.
3. 900원 기본사주·궁합으로 첫 구매 부담을 낮추고, 심층 연애운(2,900원) 등으로 구체적 관심사를 충족한다.
4. 추천받은 신규 고객이 무료 체험 후 가입하면 추천인에게 엽전을 지급해 유효한 신규 회원 확보를 유도한다.
5. 무료 오늘의 운세로 반복 방문을 유도하고 필요한 시점에 추가 상품을 안내한다.
6. 검증된 만세력 계산과 자체 해석 규칙, AI 품질 검수로 신뢰성과 일관성을 확보한다.
7. 행동 데이터로 완료율·공유율·추천 가입률·구매 전환율·상품별 수익성을 개선한다.

## 7. 지표 ↔ 이벤트 정의 (src/lib/metrics.ts)
| 지표 | 정의 | 이벤트/데이터 |
|---|---|---|
| 진입→결과 완료율 | 결과 완료 ÷ 홈 방문 | `home_view(step=home)`, `guest_trial_completed` |
| 결과→공유율 | 공유 시도 ÷ 결과 완료 | `share_intent` |
| 결과→첫 구매 | 구매 계정 ÷ 결과 완료 | `orders(status=paid)` |
| 유효 추천 가입 | 승인된 보상 수 | `rewards(approved)` |
| 부정 보상률 | 거절 ÷ 심사된 보상 | `rewards(rejected)` |
| 계산 오류율 | `calc_error` ÷ (오류+완료) | `calc_error` |
| 생성 실패율 | 실패 ÷ (성공+실패) | `report_failed`, `report_ready` |
| 첫 구매→추가 구매 | 2건 이상 구매 계정 ÷ 구매 계정 | `orders` |
| 재방문 7·30일 | 첫 운세 확인 후 N일 안 재확인 | `dailyDays` |

> 한계: 샌드박스는 이 브라우저의 이벤트만 집계한다. 실제 측정은 서버 이벤트 수집(개인정보 제외)과 코호트 분석이 필요하다.

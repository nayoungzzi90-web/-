# 명리 엔진 현황 조사 보고서 (읽기 전용 조사, 2026-10-29)

지시서 9항에 따라 **코드 수정·API 연결 없이** 현재 프로젝트를 조사했다. 가격은 지시에 따라 보지 않았고 현재 정책을 유지한다.
승인 전에는 아무것도 바꾸지 않는다.

> 먼저 알아둘 것: 이 저장소에서 `R001`, `R015` 라는 이름은 Lovable 개발 과정의 **다른 항목**을 가리켰다(R001 = 음력·절입 정밀 감사, R015 = 로그인·DB 권한·요청 제한 감사). 이번 지시서의 R-001~R-015(명리 규칙)와 **번호가 겹치지만 내용은 다르다.** 번호 체계를 정리해야 한다(7항 참고).

## 1. 현재 프로젝트 구조

| 영역 | 위치 | 상태 |
|---|---|---|
| 루트 프로젝트(Vite) | `engine/manse`(만세력), `src/lib/saju`(샘플 계산기·타입), `src/lib/report`(해석 명제·검수·AI 작성 파이프라인), `src/lib/content`(규칙형 풀이 작성기), `supabase/`(스키마·Edge Function) | 개발·시험용 |
| 실제 제품(Lovable) | `lovable-app/` (TanStack Start + Supabase). 화면, 로그인, 엽전·결제(꺼짐), 풀이 서버 함수 | 운영 DB 변경·배포 전 |
| 두 곳 연결 | `lovable-app/src/lib/reading-core/`는 루트 코드를 복사한 사본(동일성 검사 있음) | 규칙형 풀이만 연결됨 |
| AI 풀이 | `src/lib/report/*` + `supabase/functions/generate-report` | 실제 OpenAI 호출 시험 완료, **제품 화면에는 미연결** |

기술 스택: TypeScript, React 19, TanStack Start, Supabase(Postgres·Edge Function), vitest. 테스트: 루트 247개, lovable-app 163개 통과.

## 3. 기존 마스터 기준서·규칙 관련 자료

있음: `docs/CLAIM_RULES.md`(23개 해석 규칙 초안), `docs/manse/01~03`(만세력 조사·정책·검증 보고), `docs/AI_REPORT_DESIGN.md`, `docs/RELEASE_GATES.md`, `lovable-app/docs/R001_*`, `R015_*`(Lovable의 다른 R001/R015), `engine/manse/README.md`.

## 4. 누락·충돌·오류 가능성

1. **AI 풀이가 검증된 만세력을 쓰지 않는다.** 루트의 AI 작성 경로(`generate-report` Edge Function, 내가 돌린 측정 스크립트)는 **샘플 계산기**(`sampleCalculator`, 연도 경계 입춘 근사)를 쓴다. 검증된 `engine/manse`를 쓰는 것은 규칙형 풀이뿐이다. AI 풀이를 공개하기 전에 반드시 교체해야 한다.
2. **번호 충돌:** Lovable의 R001/R015(음력 정밀·보안)와 이번 명리 R-001/R-015.
3. **명리 판단이 근사:** 신강·신약을 점수 비율로 근사한다. 지시서의 "임의 점수 합산으로 판단하지 않는다" 원칙과 부딪힌다. 통근·득령 없이는 용신 판단으로 갈 수 없다.
4. **지장간 표 학파 미결정**, 해석 쪽은 본기만 사용해 엔진 자료를 활용하지 못한다.
5. **프롬프트 정책:** 현재 모델에게 "용신·격국을 새로 만들지 마라"고 지시한다. 이 방향은 지시서와 일치하지만, **대신 결정적 엔진이 그 값을 줘야 하는데** 아직 없다.
6. **대운 계산은 엔진에 있으나 해석에 연결되지 않음**(현재는 "대운 미제공" 안내 문구만).
7. **DB 불일치:** 루트 `supabase/migrations/0001~0005`(reports·generation_jobs·approved_rules 등)는 **운영(Lovable) DB에 적용된 적이 없다.** 운영에는 wallets·unlocked_readings 등 6개 표만 있다.
8. KASI 2011년 입동 1건 불일치 문의 회신 대기.
9. 모든 AI 결과가 `NEEDS_REVIEW`(승인 전 명제로 생성)라 사용자 노출 불가.

## 5. GPT + Gemini 연동 가능성

- **GPT:** 연결과 실호출 시험 완료(`gpt-5.4-mini`, 1건 약 45~60원). 서버 전용 키 방식, 비용 상한·킬스위치, JSON 스키마, 단정·용어·한자 검수 구현됨.
- **Gemini:** 코드 없음. 가능성은 높다. 이미 `LlmClient` 인터페이스가 있어 `geminiClient`를 같은 형태로 추가하면 된다. 필요: Gemini API 키(서버 비밀), 허용 도메인 `generativelanguage.googleapis.com`, 사용할 모델명, 공식 가격 확인.
- 권장 구조: **결정적 엔진 → (승인된 판단만) GPT 작성 → Gemini 검증(근거 데이터+GPT 본문을 받아 JSON 판정) → 코드가 최종 PASS/REVIEW/BLOCK 결정.** Gemini 의견은 판정을 **더 엄격한 쪽으로만** 바꿀 수 있고(PASS→REVIEW), 다수결로 판단을 확정하지 않는다. 계산 오류·출처 조작은 코드 검사로 BLOCK.
- 비용은 대략 GPT 작성 1회에 검증 1회가 더해진다(추정, 미측정).
- 개인정보: 이름은 두 모델 모두에 보내지 않는다(현재 방식 유지).

## 6. 필요한 파일·DB 변경 계획 (모두 승인 전 제안)

- 문서: `docs/SAJU_ENGINE_MASTER_SPEC.md`, 규칙별 명세 `docs/saju-engine/R-xxx.md`(원본 없는 부분은 UNVERIFIED), 용어·학파 결정 기록.
- 코드(결정적 엔진): `engine/saju-rules/` — 통근·득령, 천간 생극, 신강·신약, 격국, 억부/조후/통관/병약, 종합. 모든 판단은 `{rule_id, evidence_ids, source_version, status(CONFIRMED|CANDIDATE|WITHHELD), conflicts[]}` 구조.
- 검증기: `src/lib/report/geminiClient.ts`, `verifier.ts`, 최종 게이트(PASS/REVIEW/BLOCK).
- JSON 스키마: 판단 결과, 작성 결과, 검증 결과.
- DB(검토 전용 SQL만): `rule_registry`, `rule_judgements`, `verification_runs`(모델명·버전·프롬프트·규칙 버전·비용·판정). **운영 DB는 건드리지 않는다.**
- 테스트: 전문가 검증 정답 차트 세트(회귀), 규칙 간 충돌 검사.

## 7. 안전한 단계별 개발 순서

0. 원본 기준서 수집, **번호 체계 정리**(예: 명리 규칙은 `SJ-R001…`, Lovable 항목은 `L-R001/L-R015`로 구분)
1. 마스터 기준서 작성(모르는 부분 UNVERIFIED)
2. 공통 데이터 구조·스키마
3. R-001~R-004 정리·보강(통근·득령 추가, 지장간 표 학파 결정)
4. R-005, R-006(근사를 규칙대로 교체)
5. 격국 R-007~R-010
6. 억부·조후·통관·병약, 종합 R-011~R-014
7. 감사·승인 엔진 R-015
8. 전문가 검증 세트로 회귀 시험
9. **AI 풀이를 검증된 만세력 엔진으로 교체**
10. GPT 작성은 승인된 판단만 입력
11. Gemini 검증자, 최종 게이트
12. 서버 연결(운영 변경, 별도 승인)

각 단계는 승인 후 진행하고, 전문가 검증 없이 VERIFIED 로 바꾸지 않는다.

## 8. 사용자께 추가로 필요한 기존 기준서

1. 명리 규칙 R-001~R-015 **원본 기준서**(각 규칙의 범위·알고리즘·예외)

4. 《궁통보감》 월령 자료: 어떤 판본인지, 원문·번역 출처, 이용 가능 여부(저작권)

## 최종 질문에 대한 답

**Q. 현재 프로젝트에는 R-001~R-015의 상세 명리 규칙이 실제로 얼마나 구현되어 있으며, 정확한 전문가형 하이브리드 엔진을 완성하려면 무엇이 추가로 필요한가?**

A. 만세력 계산(절입·4주·대운·음양력)과 십성 비중 기반의 단순 해석만 구현되어 있다. 지시서 기준으로 15개 규칙 중 완전 구현은 없고, 일부·근사가 6개(R-001~R-003, R-005, R-006, R-015의 틀), 미구현이 9개(R-004와 격국·용신·조후·통관·병약·종합 R-007~R-014)이며, 전문가 검증된 규칙은 없다. 해석 규칙 23개도 전부 미승인 초안이다.
완성하려면 ① 원본 기준서와 학파 기준, ② 통근·득령부터 종합 판단까지 결정적 규칙 엔진, ③ 전문가 검증 차트 세트, ④ AI 풀이를 검증된 만세력으로 교체, ⑤ Gemini 검증기와 최종 게이트(PASS/REVIEW/BLOCK), ⑥ 규칙 승인 절차가 필요하다.

## 6. 앱이 지금 사용자에게 보여 주는 해석 계층

1. **무료 풀이(규칙 기반, `reading.ts`)**: 일간·오행 개수·월지 계절·상생상극·올해 간지·현재 대운 오행 관계만 사용. 격국·용신·신강신약·십성 의미는 쓰지 않는다.
2. **참고 표**: 십성 이름·지장간(R-003 원문 표)·대운 표, 그리고 **12운성·신살 "일반 표"**(원문 없음, 입문서 방식, 사용자 결정 2026-11-12). 풀이 문장에는 쓰지 않는다.
3. **AI 시범(소유자 전용, 기본 꺼짐, 비밀 토큰 필요)**:
   - *승인 근거 방식*: 승인(또는 시범에서 DRAFT) 명제만 쓰는 GPT 작성 + 코드 검수 + 선택적 Gemini 독립 감수. 결과가 얇다.
   - *풍부한 해석 방식*(2026-11-12 신설, 사용자 결정 A): 엔진이 계산한 사실(십성·12운성·신살·대운·올해 간지)에 **일반 명리 해석**을 AI가 붙여 길게 쓴다. 승인 명제와 규칙 엔진 판단 결과를 거치지 않는다. 코드 검수는 형식(한자·판정 용어·단정·없는 신살·마침표 등)만 막는다.
4. 일반 사용자에게 AI 풀이는 열려 있지 않다(공개 상태 변경은 승인 필요).

## 7. 데이터베이스·API

- Supabase 표 25개(마이그레이션의 `create table` 문을 세어 얻은 값): 회원·엽전·주문·결제·초대·보고서(`reports`, `generation_jobs`)·`saju_charts`·`approved_rules`(규칙 ID 단위 승인 기록)·절기 데이터·삭제 작업 등.
- `reports.status`에 `needs_review`가 있어 검수 전 초안은 사용자에게 보이지 않는다(RLS 정책).
- `approved_rules`는 해석 명제 규칙 ID(`R-CLM-*`) 승인용이며, 지시서의 JudgmentStatus 체계와는 다르다.
- 결제(`PAYMENTS_MODE`)·계정 삭제는 꺼져 있고, R-015 출시 판정은 `NO_GO`다. 이 감사에서 바꾸지 않았다.
- 서버 함수 `generate-report`(Supabase)와 `lovable-app`의 서버 풀이는 `reading-core` 파이프라인을 쓴다.

## 9. 변경 위험

- **번호·책임 불일치**: 지시서와 저장소의 R-002 정의가 다르다. 그대로 구현하면 기존 승인 기록과 어긋난다.
- **풍부한 해석 방식 ↔ 지시서 8.1·11**: LLM이 일반 지식으로 해석을 만들고 있어, 지시서의 "고객에게 보여주기 위해 새 판단을 만들지 않는다"와 충돌한다(D-2).
- **지장간 표 두 종류**: 엔진 `STANDARD`와 R-003 원문이 5개 지지에서 다르다. 통근 이후 규칙은 어느 표를 쓰느냐에 결과가 달라진다(D-7).
- **참조 코드 병합**: 현재 정책은 "병합 금지". R-008~R-015를 쓰려면 승인이 필요하다(D-10).
- **원문 부재**: 《궁통보감》 120조합과 사령 분일 수치는 원문이 없어 모델 지식으로 채울 수 없다.
- **공개 사이트**: 앱 배포 설정상 작업 브랜치가 프로덕션 분기일 수 있다(README 기준, 이번에 배포 여부는 확인하지 못했다). 푸시 전 의도 확인이 필요하다.
- 결제·삭제·DB 변경은 이 작업 범위가 아니며 하지 않았다.

5. **R-007~R-010 격국 후보**: 참조 코드 병합 승인 뒤(D-10) 시험과 함께 가져오되, 격국을 하나로 강제하지 않는다.
6. **전문가 검증 데이터**: 검증자·명식 수집·정답 표기 방식 확정 뒤 골든 세트 구축(D-12).
7. **AI 파이프라인 재정렬(PHASE 4)**: 규칙 엔진의 `Judgment`를 입력으로 받는 GPT 작성 + Gemini 독립 감수, 충돌·유보 로그. 이때 "풍부한 해석" 방식의 위치를 정한다(D-2).

각 단계는 시험을 돌리고, 결과를 숨기지 않고 보고한다. 전체 완성 표현은 검증 완료 후에만 쓴다.

## 11. 이 감사가 하지 않은 것

- 명리 규칙을 새로 정의하지 않았다. 원문에 없는 항목(사령 분일 수치, 궁통보감 조합 내용 등)은 UNVERIFIED 또는 MISSING으로 남겼다.
- `lovable-app/` 단독 시험, 배포 상태, 실제 DB 내용은 확인하지 않았다.
- 참조 코드의 시험을 재실행하지 않았다.
- 전문가 검증은 0건이며, 어떤 해석도 "검증됨"으로 표시하지 않았다.

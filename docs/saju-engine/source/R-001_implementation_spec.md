# 오행 친구들 — R-001 만세력 계산 엔진 구현·검증 보고서

**버전:** R001-CALC-0.1.0 (2026-10-16)

**분류:** 실동작 계산 코어 + 외부 검증이 일부 완료된 **출시 전 후보**. 사용자의 R-001 정책 채택은 코드 정확성의 최종 인증과 구별한다.

## 1. 확정된 계산 정책

- 입력: 그레고리력 양력 연월일과 **해당 장소의 당시 법정시**, 입력 포맷 `YYYY-MM-DDTHH:mm[:ss[.SSS]]`.
- MVP 지역: 한국 `Asia/Seoul`. 한국 이외 지역·북한·해외 출생 및 특수 지역 정책은 별도 모듈 필요. 음력 입력을 양력으로 변환하는 기능은 이번 R-001 코어에 **없다**.
- 지원 출생 연도: 1900–2100. 1899–2101 천문 표는 전후 경계를 위한 데이터 포함.
- 24절기: 황경 285°(소한), 300°(대한), 315°(입춘), 이후 15° 간격... 270°(동지)인 **지구중심 겉보기 태양 황경** 도달 시각(UTC epoch ms).
- 년주: 입춘 순간 이전=전년도 간지, 입춘 순간 포함 이후=새해 간지. 1984 입춘 이후 甲子년.
- 월주: 12절 **소한·입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설**를 시작으로 월 변경. 입춘=寅, ... 대설=子, 소한=丑. *우수·춘분 등의 중기에는 월주 미변경.*
- 월간: 甲/己년 丙寅, 乙/庚년 戊寅, 丙/辛년 庚寅, 丁/壬년 壬寅, 戊/癸년 甲寅.
- 일주: 2000-01-07 **甲子日** 기준, 60일 순환; 기본 자정 교체. `late_zi_next_day`가 명시된 경우 23:00부터 새 일주와 그 일간의 子시 적용. 정책 명시 없이는 23:00 방식 적용하지 않음.
- 시지: 23:00–00:59 子, 01:00–02:59 丑 ... 21:00–22:59 亥. 시간간은 일간별 子시 시작 천간 + 2시간 단위 순차.
- `[시작,다음 시작)`을 경계 구간으로 적용. 정확한 절입 시각과 전후 1초는 분리 계산한다. 외부 공식 참조가 분 단위이므로 절입 ±120초는 **운영 검토 플래그**.
- 시간대: IANA `Asia/Seoul`과 서버 Intl/ICU 규칙을 사용. 존재하지 않는 법정시를 거부하고, 중복된 시각은 `earlier`/`later` 명시 요구.
- **정오·23시·입춘에 민감한 진태양시/경도 보정은 미구현.** '법정시 기준'으로만 표시. 필요한 경우 별도의 정책·지리 좌표와 교차검증이 필수.

## 2. 천문 자료 획득과 공식 교차검증

### 계산 데이터

`solar_terms_1899_2101.json`: 203개 연도 ×24 = **4,872개** 태양 황경 교차 시각을 계산한 결과값. 생성기는 `generate_terms.py`; **pyswisseph 2.10.03**의 `solcross_ut(..., FLG_MOSEPH)`로 생성. 스위스 천체력의 Moshier 계산을 선택하여 ephemeris 파일 자동 fallback을 피했다. **한국천문연구원 데이터의 일괄 복제물이 아니다.** 태양 황경·ΔT 모델의 불확실성과 버전 의존성이 있어 KASI 교차 대조를 수행했다.

### 독립 검증

- KASI 공개 달력자료 **2025, 2026, 2027년 24절기 72개 시각**과 검증. 월일시분까지 모두 일치하는 분 단위 자료(각 차이 절댓값 `<60초`; 최대 **30.017초**, 평균 약 **14.456초**). *출력 초·밀리초에 대한 공식적 일치 증명은 아님.*
- KASI 2026년 월별 음력 초하루의 **일진 12개**와 독립 대조.
- 별도 라이브러리 `korean-lunar-calendar`로 생성한 **7,200개** 양력 일자(1900~2049)의 일진을 비교, 전부 일치. 음력 변환/음력 월주 판정은 검증하지 않음.
- 국립 역서 또는 천문연구원 공식 월력요항 및 다른 독립 천문 계산 엔진과 1900–2100 전 범위를 교차검증하는 작업은 **미완료**.

공식 참조: 
- KASI 2025 https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2025
- KASI 2026 https://astro.kasi.re.kr/kor/life/post/calendarData?year=2026
- KASI 2027 https://astro.kasi.re.kr/kor/life/post/calendarData?year=2027
- IANA https://data.iana.org/time-zones/tzdb/tz-link.html

KASI가 공개 달력자료를 공식 공고용 월력요항과 구분하여 설명하는 점을 보존한다.

## 3. 시간대 및 야자시 검증

- 1909년 `+08:30`, 1915년 `+09:00`, 1954년 `+08:30`, 1955년 DST `+09:30`, 1988년 DST `+10:00` 사례 포함.
- 1948년 여름시간 시작 당시 사라지는 시각 거부.
- 1954년 30분 시각 중복 상황은 명시적 선택을 요구.
- 1988년 5월 서머타임 시작 `02:30` 거부 및 10월 종료 중복 `02:30` 명시 선택.
- IANA 표준시는 1970년 이전 지역별 자료에 한계가 있으며 별도 법령 및 사료 검증이 필요. `historicalTimeZoneReview=true` 표기.
- 런타임 ICU/tzdb 데이터는 업데이트되면 과거 시각 결과가 달라질 수 있다. 예시 시험 런타임: Node.js v22.16.0, ICU 77.1, tzdb 2025b. **실제 배포에서는 시간대 데이터 버전 고정·기록/회귀검사가 필요**.

## 4. 소프트웨어 구현 구성

| 파일 | 용도 |
|---|---|
| `oheng_r001.ts` | 순수 계산코어 (`calculateR001`, `calculateDay`, `calculateHour`, `civilToUtc`) |
| `solar_terms_1899_2101.json` | 연도별 24절기 UTC epoch milliseconds 고정 데이터 |
| `generate_terms.py` | 공개된 천문 계산 라이브러리로 자료를 재생성하는 스크립트 |
| `kasi_reference_minutes_2025_2027.json` | 독립 참조 72개 자료와 출처 |
| `day_reference_1900_2049.json` | 7,200개 일진 독립 참조 |
| `oheng_r001_tests.js` | 25개 테스트 그룹, 절입·시간대·일진 등 |
| `supabase/functions/r001-preview/index.ts` | 비공개 사용자 인증 후 **미승인 프리뷰만 제공하는 예제**, 배포 및 실환경 테스트 **미실시** |

`R001Error.code` 사례: `INVALID_FORMAT`, `INVALID_DATE`, `NONEXISTENT_LOCAL_TIME`, `AMBIGUOUS_LOCAL_TIME`, `OUT_OF_RANGE`, `MISSING_EPHEMERIS`, `UNSUPPORTED_ZONE`.

### 로컬 검증 방법

```bash
npm install
npm test
```

TypeScript 5.8.3과 Node.js 22 시험 환경. Deno/Supabase Edge 빌드·배포·RLS·인증·Rate Limit·실제 API 부하는 **추가 테스트**가 필요하다.

### 참조 결과 사용 예

```ts
import { calculateR001 } from './oheng_r001';
import termData from './solar_terms_1899_2101.json';

const result = calculateR001(
  { local: '2000-01-07T12:00:00', zone: 'Asia/Seoul', dayRollover: 'midnight' },
  termData
);
// year 己卯, month 丁丑, day 甲子
// status === 'calculated_review_required', not production-approved
```

## 5. Gate R-015: 운영 승인 차단 조건

- **NO-GO:** 정밀 절입 시각의 공식/독립 소스 교차검증 범위 부족, tzdb 공급원/버전 미고정, 결제/해석 연결 미검증, 법정시 역사 검증 미완료, R001이 개인 정보를 DB에 남기는 방식의 RLS 미검증.
- **절입 ±120초:** 공식 참조가 분 단위이고 초 단위 기준이 다를 수 있으므로 명리학 결과 확정 대신 잠정·재검토.
- **1970년 이전 출생:** 과거 법정시·지역별 기록·DST를 별도로 검토.
- **달력 변환:** 음력 출생 입력이 들어오면 별도 양력 변환·윤달·지역·법정시 검증 없이는 R001 호출 금지.
- **해외 출생:** `Asia/Seoul`로 강제 변환하지 않음. 외부 지역 지원 전에는 입력 거부.
- **유료 결과:** 현재 R001 구현은 `calculated_review_required`이므로 유료용 원국 확정 또는 자동 해석으로 연결하지 않음. R015 서명된 서버 승인 후 별도 엔진 래핑 필요.

## 6. 아직 필요한 추가 운영 검증

1. KASI 공식 역서 또는 별도 고정밀 천문 계산으로 1900~2100 주요 경계 다년 교차검증 및 모델 오차 한계 평가.
2. KASI 분 단위 표현의 반올림/절삭 정책을 출처와 함께 확인, 근접 경계 보수적 처리.
3. 지역별 법정시 및 역사적 법령과 tzdb 판본 일치, 1900 이전·북한·외국 입력 별도 지원 범위 결정.
4. `true solar time`, 날짜 경계(23/00), 야자시 처리 방침에 대한 명리학 전문가 정책 서명.
5. Server/Deno Edge 함수 실환경 검사, 인증/RLS/Rate Limit/프리뷰 남용 차단, 입력·삭제·로그 개인정보 점검.
6. 별도 만세력 엔진과 4주 전체 장기 회귀테스트 후 R-015 출시 게이트를 통과한 범위에서만 활성화.

**이 구현 결과는 2026년 10월 16일 검증 시점의 실행 가능한 계산 후보이며, 전연도·전지역 운영 승인을 선언하지 않는다.**

## 7. 상용 서비스의 천문 라이브러리 라이선스 점검

- 본 패키지의 **런타임 TypeScript 계산 코어에는 Swiss Ephemeris 자체를 내장하지 않았다.** UTC 절기 계산 결과값(JSON)을 읽는다.
- 그러나 `generate_terms.py` 재생성 스크립트는 `pyswisseph`에 의존하며, Swiss Ephemeris 원 소프트웨어는 AGPL 또는 상용 Professional 라이선스를 선택하도록 안내한다. 해당 라이브러리를 서비스에서 직접 사용하거나 재생성 파이프라인을 배포할 때 라이선스·AGPL 의무·상용 사용 조건을 검토해야 한다.
- 산출된 숫자 데이터의 재배포/이용에 관한 계약상 조건도 **법률 검토 없이 자유 사용으로 단정하지 않는다.** 필요하면 MIT 라이선스 천문 계산 엔진(Astronomy Engine 등)으로 독립 재생성하고 KASI 자료와 재검증하는 대체 경로를 설계할 수 있다.

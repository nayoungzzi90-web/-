# 오행 친구들 — R-001~R-015 복원 통합 마스터 기준서

작성일: 2026-10-29

## 복원 상태 및 신뢰 경계

이 문서는 실제 보관된 과거 문서를 **원문 그대로** 결합하고, 원문이 발견되지 않은 단계는 이전 사용자 채택 정책을 바탕으로 **요약 복원**한 자료다. 전체 15개 세부 원문이 모두 확보됐다는 의미가 아니다. 문헌과 소스 구현의 승인 상태를 혼동하지 않는다.

- **원문 확보:** R-001 구현·검증 보고서, R-010~R-015 상세 명세서. 단 이 문서들에도 DRAFT/미검증 항목이 있으며 최종 운영 승인 상태가 아니다.
- **원문 미확보:** R-002~R-009의 개별 상세 원문. R-008/009 TypeScript 참조 소스는 별도 ZIP의 R-015 전체감사 번들에 보관되어 있다.
- **정책 복원:** R-002~R-005의 이전 사용자 채택 원칙 및 R-006~R-009의 요약된 방향. 이 부분은 세부 수학·시간 경계·예외 알고리즘을 새로 지어내지 않는다.
- **운영 상태:** R-015 원본 문서는 NO_GO. 승인된 *정책*과 운영 출시 허가는 다르다.

## Claude Code에 대한 최우선 지시

1. 기존 프로젝트와 이 문서 및 동봉 원본 명세들을 읽고 충돌·누락·구현 상태를 분리하여 감사한다.
2. 원문 확보 섹션은 그대로 추적하고, DRAFT/NO_GO/미검증 상태를 임의로 APPROVED로 바꾸지 않는다.
3. 상세 원문이 없는 R-002~R-009는 `SOURCE_MISSING`으로 분류하고, 참조 코드가 있는 경우에도 문서 완전 복원을 주장하지 않는다.
4. 구현 전 분석 보고서를 제공한다. 기존 코드 및 DB, API 키, 결제 로직은 승인 없이 수정하지 않는다.
5. GPT는 규칙 기반 판단 데이터의 상담문 생성자, Gemini는 독립 분석·감수자. 두 모델 모두 원국·격국·용신 최종 판정 권한 없음.
6. 서버 측 API 연결과 JSON 스키마 검증, evidence_id 계보, 미승인 claim 발행 차단을 설계한다.
7. R-015의 Gate0~6 및 C01~C18, NO-GO/LIMITED-GO/GO 정책을 보존한다.

## 복원된 의존 그래프

입력→ R001 → {R002,R003,R005} → R004 → R006(초기) → R007/R008 → R009(특수격 후보) → R006(재평가) → R010 → {R011,R012,R013} → R014 → R015.

정확한 선후 의존성은 아래 R-015 원문을 우선한다. R-006 ↔ R-009는 무한 순환 호출이 아니라 제한된 상태 전이로 다룬다.


# R-002~R-009 채택 정책 복원(상세 원문 미확보)

**주의:** 이 섹션은 이전 대화에서 확인된 채택 정책의 복원본이며, 세부 소스 텍스트를 재현한 문서가 아니다. 각 단계의 원본 규칙표·전수 예외·실제 구현 테스트 조건은 `SOURCE_MISSING` 또는 `IMPLEMENTATION_REVIEW_REQUIRED`로 관리한다.

## R-002 월령·계절 세력
- 월령과 계절이 오행에 미치는 영향을 계산 사실 및 질적 관계로 기록한다.
- 일간의 득령/旺相과 원국 전체의 최종 신강·신약은 별개다. 월령만으로 강약을 확정하지 않는다.
- `월령 계절 영향` 및 `실제 세력`을 별도 데이터로 표현한다.
- **미복원:** 월령별 구체 판정표, 예외 조건, 승인된 출력 스키마.

## R-003 지장간·사령 분일
- **고정 지장간 표:** 《연해자평》 기반 출처 관리.
- **사령 분일:** B형 분일표를 기본 *후보*로 두고 A형 《삼명통회》와 비교한다.
- 절입 시각 이후 경과시간 비례배분을 활용한다. 달력 날짜만으로 경계 계산하지 않는다.
- B형 미검증 구간은 전문가 검증 전 계산 사실로 승격 금지. 분일표 버전·이견을 기록한다.
- 사령 하나만으로 격국·용신 확정 금지. 고정 지장간과 사령 분일을 서로 다른 출처와 버전으로 유지.
- **미복원:** B형 전 구간 분일 수치, A/B 분일 비교표, 경계 테스트의 완전 원문.

## R-004 구조적 통근·득지
- 통근은 천간과 지장간 간 **구조적 존재**로 기록한다. 단순 생조(예: 水生木)는 통근이 아니다.
- 본기근/중기근/여기근과 정확 천간 일치/동오행 관계를 분리한다.
- 합·충 존재만으로 통근 자동 삭제 금지. 합충의 작용 가능성/실제 성립 구분.
- 통근 개수의 임의 점수화 금지.
- **미복원:** 12지지별 상세 강도/위치 우선순위 원문, 확정 효력 판정 알고리즘.

## R-005 천간 생극·합화·구조 후보 (DRAFT-2 채택)
- 상대 천간의 생조, 극설, 소모 및 득세를 위치·거리와 **여섯 쌍의 천간 관계**를 고려해 기록.
- 일간 자신을 네 천간에 포함된 또 하나의 별도 비견으로 중복 계수하지 않음.
- 간합 후보와 합화 성립을 구분하고, 합화 조건 미검증 시 확정 금지.
- 살인상생·식신제살·재극인 등은 구조적 후보를 탐지하되 실제 성립과 유불리는 유보.
- **미복원:** 거리/위치 간 정확 알고리즘, 여섯 쌍 매핑 세부표, 각 구조의 승인된 완전 성립 조건.

## R-006 신강·신약·중화
- 득령·통근·천간 관계를 질적으로 종합, 증거와 반증을 함께 기록.
- 일반 강약의 1차 후보 판단 → R-009 특수격 후보 검토 → R-006의 한정된 재평가(상태/버전 추가).
- 종격 미해결 시 일반 억부의 최종 확정 차단. 임의 점수 합산 금지.
- **미복원:** 신강/신약/중화 최종 경계와 이견 해소의 구체 규칙, 테스트 원문.

## R-007 기본 격국 후보
- 월령 및 지장간·투출 등 구조에 따라 격국 후보를 만든다.
- 월지 본기 후보를 최종 격국으로 자동 확정하지 않는다; R-010 서명 전 `final_geju = null`.
- **미복원:** 기본격 취격 분기·예외의 전체 원문.

## R-008 투간·회합·잡기 후보
- R-001/R-003/R-007이 검증한 원국을 입력으로 받은 후보 탐지기.
- 지장간의 **동일 천간 투출(exact)**, **동오행 노출(related)**, **합화(transformation)**를 분리.
- 辰戌丑未 잡기, 회합, 격국 성립 가능성을 기록하되 최종 취격이나 합화 성립을 주장하지 않는다.
- 참조 코드: `UPSTREAM_R008_R014/oheng_r008.ts` (동봉 감사 ZIP).
- **미복원:** 사용자 승인 상세 기준서 원문. 코드 ≠ 승인된 명리 정책.

## R-009 특수격 후보
- 참조 코드가 다루는 후보: 建祿, 月劫, 羊刃, 從財, 從官, 從兒, 從勢, 從强, 從混, 假從 재검토.
- 후보 탐지만 수행하며 `status: review_required`, `final_pattern: null`, `final_follow_status: not_evaluated`를 유지.
- 甲卯의 월겁·양인 중첩 등 복수 후보를 하나로 임의 삭제하지 않는다.
- 참조 코드: `UPSTREAM_R008_R014/oheng_r009.ts` (동봉 감사 ZIP).
- **미복원:** 특수격 승인 성립/파격 전수 조건·예외의 원문.

# 오행 친구들 — R-001 만세력 계산 엔진 구현·검증 보고서

**버전:** R001-CALC-0.1.0 (2026-10-16)

**분류:** 실동작 계산 코어 + 외부 검증이 일부 완료된 **출시 전 후보**. 사용자의 R-001 정책 채택은 코드 정확성의 최종 인증과 구별한다.

## 1. 확정된 계산 정책

- 입력: 그레고리력 양력 연월일과 **해당 장소의 당시 법정시**, 입력 포맷 `YYYY-MM-DDTHH:mm[:ss[.SSS]]`.
- MVP 지역: 한국 `Asia/Seoul`. 한국 이외 지역·북한·해외 출생 및 특수 지역 정책은 별도 모듈 필요. 음력 입력을 양력으로 변환하는 기능은 이번 R-001 코어에 **없다**.
- 지원 출생 연도: 1900–2100. 1899–2101 천문 표는 전후 경계를 위한 데이터 포함.
- 24절기: 황경 285°(소한), 300°(대한), 315°(입춘), 이후 15° 간격... 270°(동지)인 **지구중심 겉보기 태양 황경** 도달 시각(UTC epoch ms).
- 년주: 입춘 순간 이전=전년도 간지, 입춘 순간 포함 이후=새해 간지. 1984 입춘 이후 甲子년.
- 월주: 12절 **소한·입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설**를 시작으로 월 변경. 입춘=寅, ... 대설=子, 소한=丑. *우수·춘분 등의 중기에는 월주 미변경.*
- 월간: 甲/己년 丙寅, 乙/庚년 戊寅, 丙/辛년 庚寅, 丁/壬년 壬寅, 戊/癸년 甲寅.
- 일주: 2000-01-07 **甲子日** 기준, 60일 순환; 기본 자정 교체. `late_zi_next_day`가 명시된 경우 23:00부터 새 일주와 그 일간의 子시 적용. 정책 명시 없이는 23:00 방식 적용하지 않음.
- 시지: 23:00–00:59 子, 01:00–02:59 丑 ... 21:00–22:59 亥. 시간간은 일간별 子시 시작 천간 + 2시간 단위 순차.
- `[시작,다음 시작)`을 경계 구간으로 적용. 정확한 절입 시각과 전후 1초는 분리 계산한다. 외부 공식 참조가 분 단위이므로 절입 ±120초는 **운영 검토 플래그**.
- 시간대: IANA `Asia/Seoul`과 서버 Intl/ICU 규칙을 사용. 존재하지 않는 법정시를 거부하고, 중복된 시각은 `earlier`/`later` 명시 요구.
- **정오·23시·입춘에 민감한 진태양시/경도 보정은 미구현.** '법정시 기준'으로만 표시. 필요한 경우 별도의 정책·지리 좌표와 교차검증이 필수.

## 2. 천문 자료 획득과 공식 교차검증

### 계산 데이터

`solar_terms_1899_2101.json`: 203개 연도 ×24 = **4,872개** 태양 황경 교차 시각을 계산한 결과값. 생성기는 `generate_terms.py`; **pyswisseph 2.10.03**의 `solcross_ut(..., FLG_MOSEPH)`로 생성. 스위스 천체력의 Moshier 계산을 선택하여 ephemeris 파일 자동 fallback을 피했다. **한국천문연구원 데이터의 일괄 복제물이 아니다.** 태양 황경·ΔT 모델의 불확실성과 버전 의존성이 있어 KASI 교차 대조를 수행했다.

### 독립 검증

- KASI 공개 달력자료 **2025, 2026, 2027년 24절기 72개 시각**과 검증. 월일시분까지 모두 일치하는 분 단위 자료(각 차이 절댓값 `<60초`; 최대 **30.017초**, 평균 약 **14.456초**). *출력 초·밀리초에 대한 공식적 일치 증명은 아님.*
- KASI 2026년 월별 음력 초하루의 **일진 12개**와 독립 대조.
- 별도 라이브러리 `korean-lunar-calendar`로 생성한 **7,200개** 양력 일자(1900~2049)의 일진을 비교, 전부 일치. 음력 변환/음력 월주 판정은 검증하지 않음.
- 국립 역서 또는 천문연구원 공식 월력요항 및 다른 독립 천문 계산 엔진과 1900–2100 전 범위를 교차검증하는 작업은 **미완료**.

공식 참조: 
- KASI 2025 https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2025
- KASI 2026 https://astro.kasi.re.kr/kor/life/post/calendarData?year=2026
- KASI 2027 https://astro.kasi.re.kr/kor/life/post/calendarData?year=2027
- IANA https://data.iana.org/time-zones/tzdb/tz-link.html

KASI가 공개 달력자료를 공식 공고용 월력요항과 구분하여 설명하는 점을 보존한다.

## 3. 시간대 및 야자시 검증

- 1909년 `+08:30`, 1915년 `+09:00`, 1954년 `+08:30`, 1955년 DST `+09:30`, 1988년 DST `+10:00` 사례 포함.
- 1948년 여름시간 시작 당시 사라지는 시각 거부.
- 1954년 30분 시각 중복 상황은 명시적 선택을 요구.
- 1988년 5월 서머타임 시작 `02:30` 거부 및 10월 종료 중복 `02:30` 명시 선택.
- IANA 표준시는 1970년 이전 지역별 자료에 한계가 있으며 별도 법령 및 사료 검증이 필요. `historicalTimeZoneReview=true` 표기.
- 런타임 ICU/tzdb 데이터는 업데이트되면 과거 시각 결과가 달라질 수 있다. 예시 시험 런타임: Node.js v22.16.0, ICU 77.1, tzdb 2025b. **실제 배포에서는 시간대 데이터 버전 고정·기록/회귀검사가 필요**.

## 2. 판정 요소

기본 결과는 `establish_candidate`, `obstruct_candidate`, `rescue_candidate`, `mixed_unresolved`, `insufficient_evidence` 가운데 하나이다. 이는 *전통 해석상 후보를 검토한 결과*이며 성격/파격의 최종 승인값이 아니다.

- 성립 근거: `establish` 규칙을 만족하는 조건.
- 손상 근거: `obstruct` 규칙을 만족하는 조건. 요소의 존재만이 아니라 **효력 확인**이 요구됨.
- 구응 근거: `rescue` 규칙으로 특정 손상 규칙의 효력을 완화하는지 검토. 어느 손상 규칙을 해소하는지 반드시 참조.
- 겸격·순잡: 복수 후보의 존재와 상생·제어·간섭의 실효성을 별도 검사. 겸격 후보의 수로 청탁·순잡을 자동 결정하지 않음.

## 3. 격국별 원전 기반 규칙 요약

이 표는 **후속 세부 조건을 포함한 완성된 필요충분조건이 아니며**, 전문가가 검증할 루트 후보를 표기한 것이다.

| 정관 | 재생관·인호관; 형충 손상 없음 | 상관극관·형충, 관살 혼잡, 관성이 간합으로 제약됨 | 인성이 상관의 제약을 해결; 합살유관; 검증된 회합해충 |
| 재(정재·편재) | 재생관; 식신생재+일간 조건; 재인불애 | 재약+비겁 과중; 재생살로 인해 문제 발생 | 식상화겁생재, 관을 통해 비겁 제약, 제살/합살 |

**후속:** R-012 억부용신, R-013 조후·통관·병약, R-014 이론별 결론 비교

> 이 문서는 전통 명리학 내부의 해석 규칙을 일관되게 적용하기 위한 소프트웨어 설계다. 운세의 실증적 예측 정확성을 입증하거나 보증하지 않는다.

## 1. 문헌 근거와 출처 구분

### 1.1 《자평진전》 원문
- 「논상신긴요」: 월령에서 취한 격국의 중심을 돕는 다른 요소를 상신이라 부르며, 격국이 그 요소에 의지해 성립하는 경우를 설명한다. 재생관에서 재가 상, 재격생관에서 관이 상, 살을 식으로 제할 때 식이 상이라는 *기초 예시*를 제시한 후 이 방식이 고정된 유일 공식은 아니라고 경고한다.
- 해당 장은 또 천간의 합·제·구응 이외에 `癸生亥月 ... 卯未來會`, `庚生申月 ... 子辰會局` 같은 **지지 결합 상신** 사례를 수록한다.
- 「논용신성패구응」: 성립·방해·구응을 분리한다. 상신 후보를 뒷받침하는 증거와 상신의 실제 효력은 동일하지 않다.
- 「논용신변화」·「논용신인성득패인패득성」: 월령 취격 자체가 변화할 수 있고, 구성이 좋아 보여도 간섭으로 반전될 수 있다.
- 「논사길신능파격」·「논사흉신능성격」: 십성이 길신/흉신이라는 이름만으로 유리·불리를 고정하지 않는다.

### 1.2 서락오의 《자평진전평주》
- 「논상신긴요」의 *서주(徐注)*에서 상신을 희신이라고 부르고, 재관식인 등의 협력과 구응을 설명한다.
- 여기서의 ‘희신’이라는 표현을 현대 억부·조후 분석에서 사용하는 희신과 자동으로 동일시하지 않는다.
- 서주의 “《삼명통회》 정관격에 재를 인도 요소로, 인을 보호 요소로 본다”는 언급은 **서락오의 인용·해석**으로 저장한다. 별도로 《삼명통회》 원문 확인 없이 특정 문구를 직접 인용하는 것으로 기록하지 않는다.
- 후대 평주가 조후용신을 격국 중심의 용신으로 넓게 설명하는 대목은 원저자인 심효첨의 월령용신과 명시적으로 분리한다.

### 1.3 판본 및 문자 이견
- 「논상신긴요」의 `庚生申月 透水`는 일부 판본에서 `透癸`로 교감한다.

- 텍스트 원문·후대 주석·현대 운영 정책을 `source_layer`로 구분한다.

## 2. 용어와 타입

**`geju_core`**: R-007~R-010의 취격 근거에서 발생하는 *격국 중심 후보*. 확정 전에 특정 천간 하나에 단정하지 않는다.

**`xiangshen_candidate`**: 승인된 성격·구응 경로와 실제 행위 주체(actor)를 연결한 상신 *후보*. `actor`는 천간, 지장간, 지지 결합, 특정 합·제 작용일 수 있다.

**`xiangshen_effective`**: 그 후보가 실제 해당 성격·구응 경로를 수행하는지 승인된 별도 규칙으로 확인된 경우에만 사용하는 상태. 현재 R-011에서는 운영용 확정으로 승격하지 않는다.

**`damage_to_xiangshen`**: 특정 상신 후보가 다른 관계에 의해 기능을 잃거나 훼손될 가능성. `관계 존재`와 `효력 확인`을 따로 기록한다.

**`rescue_to_damage`**: 손상 A에 대한 별도의 구응 B를 연결한다. 다른 손상을 자동 해소하지 않는다.

**`indispensability`**: '이 행위 주체를 제거했을 때 승인된 다른 독립 경로가 존재하는가?'를 확인하는 별도의 반사실 검토. 아직 자동 산정하지 않는다.

## 3. 격국별 상신 선정 경로 (후보 심사표)

| 격국 중심 후보 | 성격/구응 경로 | 상신 후보의 역할 | 필수 검토·파상신 후보 |
|---|---|---|---|
| 정관격 | 재생관 | 재성 | 재성에 대한 비겁의 제약, 재인 간섭, 관성 손상 |
| 정관격 | 인성이 관성을 보호/상관 제어 | 인성 또는 확인된 제약·합의 주체 | 상관 효력, 인성의 재극인·간합, 관살혼잡 미해결 |
| 재격 | 재성생관 | 관성 | 관살혼잡, 관성에 대한 극제·합거 |
| 재격 | 식신생재 | 식상 | 식상의 통근, 인성의 극제, 일간 강약의 유효성 |
| 인격 | 관인상생·살인상생 | 관성·칠살 | 인성 필요성, 재극인, 살인상생의 효력 |
| 인격 | 인성 과다에서 식상설기·재로 제약 | 식상·재성 후보 | **현 R-010에 해당 세부 경로 부족**: 확정 보류 |
| 식신격 | 식신생재 | 재성 | 재성의 작용, 편인도식, 제살과 경쟁 |
| 식신격 | 식신제살 | 독립 상신 없음 또는 기타 구응 후보 | 식신 자체가 중심의 작용일 수 있어 자동 상신 배정 금지 |
| 칠살격 | 식신제살 | 식신 | 제살 유효성, 편인도식, 재생살, 일간 조건 |
| 칠살격 | 살인상생 | 인성 | 인성의 통근·재극인 및 식신제살과 경쟁 |
| 상관격 | 상관생재 | 재성 | 재성 합거, 상관의 효력, 관살의 간섭 |
| 상관격 | 상관패인 | 인성 | 인성 뿌리, 재극인, 강약 조건 |
| 양인격 | 관살제인 | 관성·칠살 | 관살의 합거·상관 극제, 인성 보호 여부 |
| 건록·월겁 | 관 활용 | 관성 | 관성 혼잡·파손, 재인 보조 |
| 건록·월겁 | 식상생재·제살 | 식상 등 승인된 경로의 실제 보조 요소 | 합충·제살·재성 유효성 |

이 표는 최종 단일 상신 추천표가 아니다. 격국 성립 경로가 승인되지 않으면 상신도 후보에 머문다.

## 4. 고전의 대표 증거와 반증

### 4.1 甲日 酉月, 丁傷官, 壬印
- 酉의 辛은 정관의 중심 후보이고, 丁은 그 정관을 극할 수 있는 상관이다.
- 壬이 丁과 합하여 장애를 해소하는 작용이 검증된다면 壬을 상신 후보로 검토할 수 있다.
- 丁壬合의 *발견*만으로 합거·구응을 확정하지 않는다.

### 4.2 甲日 酉月, 丁傷官, 癸印, 戊財
- 癸가 丁을 제어해 정관을 보호하는 경로라면 癸가 상신 후보가 된다.
- 戊癸合으로 癸의 보호 효력이 손상될 수 있는지 검토한다. 합 발견은 손상 확정과 다르다.
- 손상 경로가 검증돼도 다른 구응·성격 경로를 모두 검토하기 전에는 최종 파격을 확정하지 않는다.

### 4.3 丁日 酉月, 癸殺, 己食, 甲印
- 己가 癸를 제어하는 구조라면 己는 구응/상신 후보가 될 수 있다.
- 甲己合으로 己의 제살 기능이 방해받는 가능성을 검사한다.

### 4.4 戊日 子月, 甲殺, 己劫
- 己甲合의 합살존재(合煞存財) 구조가 적절하게 작용한다면 己가 구응형 상신 후보가 될 수 있다.

### 4.5 癸日 亥月 丙財, 卯未 회합 및 庚日 申月 子辰 회합
- 상신이 꼭 천간 한 글자인 것은 아니다. 지지 결합이나 회합이 격국의 성립을 돕는 것으로 해석되는 사례가 있다.
- R-008에서 탐지한 회합은 실제 성립·유효성 미확정 상태이며 R-011에서 바로 `confirmed`로 승격하지 않는다.

## 5. 파상신 및 구응의 규칙

1. 손상은 **상신 후보의 특정 actor ID**에 연결한다. 같은 오행이라는 이유로 다른 천간의 효력을 소멸시키지 않는다.
2. `damage.state=unknown`은 공격·합·충 등의 존재/검토 후보를 뜻한다. `confirmed`는 *승인된 효력 규칙*과 근거 ID가 있어야 한다.
3. 손상 효력이 확인되어도 `격국 최종 파격=true`를 즉시 반환하지 않는다. 다른 대체 경로·구응이 남아 있을 수 있다.
4. 구응은 `attackId → mitigationId`로 연결한다. 구응 B가 미확정이면 손상 A도 자동 해결되지 않는다.
5. 같은 actor가 여러 후보 격국에서 다른 역할을 할 수 있다. 역할을 후보 격국 ID별로 기록한다.
6. 상신 후보가 둘 이상이면 하나를 숫자 점수로 골라내지 않는다. R-010의 성립 경로, 성패, 필수성, 파손 상태를 비교한다.
7. 합의 후보와 합화의 성립은 다르고, 운의 작용을 원국의 상신 판정에 임의로 섞지 않는다.

| 심효첨 《자평진전》 | 월령용신 중심, 격 성립의 필요 요소가 상신, 천간 및 지지 결합 사례 | 주 분석 체계 |

## 7. 개발 알고리즘과 데이터 계약

### 7.1 선행 입력
- R-010의 후보별 `establishedRoutes`, `obstructedRoutes`, `rescuedLinks`, `unresolvedObstructions`, `pendingRoutes`.
- 각 경로의 실제 행위 주체 `actor` 및 근거 노드 (`actorId`, 천간/지지/지장간/지지결합, `sourceNodeIds`).
- `routeId → actorId` 연결: 해당 경로가 **어떤 실제 천간/지지**에 의해 이루어지는지 기록.
- 상신 훼손 `DamageEdge`, 훼손의 구제 `MitigationEdge`.
- 서버 제공 승인 규칙 목록(`trustedRuleIds`). 사용자가 임의 전달한 승인 ID를 신뢰하지 않는다.

### 7.2 상태 계산
1. 검증된 R-010 결과가 없으면 R-011 실행 차단.
2. 각 후보 격국을 유지하고 `geju_core_candidates`로 기록. 아직 단일 용신 확정 금지.
3. R-010 활성 성립 경로 혹은 원인 손상을 실제로 해결한 구응 경로만 상신 경로로 연결.
4. 경로에 연결된 actor의 유형·십성 계열이 승인된 후보 정책과 맞는지 검사.
5. 승인된 경로 및 승인된 주체 효력이 일치하면 `route_supported_candidate`.
6. 상신 후보에 대한 손상효력이 불확실하면 `damage_review_required`.
7. 승인된 손상 효력이 유효하면 `damage_supported_review`로 재심사. 최종 파격을 확정하지 않음.
8. 특정 손상에 대한 구응이 승인되면 해당 손상만 `mitigatedDamageIds`에 기록.
9. 격국 자체의 다른 미해결 손상, 여러 활성 경로, 중복 원천은 모두 보존.
10. `finalXiangshen`, `gejuYongshen`, `finalGeju`는 현재 버전에서 `null`. 운영 승격은 후속 전문가 승인 규칙과 통합 테스트가 요구됨.

### 7.3 필요한 추가 엔진/미완료 의존성
- R-006 종합 신강신약 확정 규칙(현재 후보 중심)
- R-008 천간 합화·지지 회합의 실제 작용 확정 규칙
- R-009 특수격 진종/가종 불성립 기준
- R-010의 격국 최종 성패 판정 (현재 후보)
- 인격의 식상설기/인과다 용재 등의 세부 R-010 경로 확대
- 복수 상신 후보의 **필수성·대체 가능성** 검증(독립 경로/반사실 평가)
- 원문 판본·후대 주석별 승인 및 전문가 검토

## 8. 테스트 및 운영 승인

**기초 단위 테스트**
- 정관 재생관 / 상관 손상 후 인성 구응
- 정관 상관 손상 외 다른 손상까지 구응하지 않는지 검사
- 丁壬合·戊癸合·甲己合 후보와 확정 효력 구별
- 인성, 재성, 칠살, 식상 등 여덟 격국의 후보 경로 검사
- 지지 결합 `branch_group` 유형 허용
- 승인되지 않은 효과 신호 차단
- 복수 상신/복수 격국 후보 보존
- 미확정 경로에서 상신 자동 확정 금지
- 동일 입력·버전에서 동일 반환값 확인

**참조 구현 결과**: 타입스크립트 모듈 및 테스트 파일 별도 제공. 합성 테스트에서 통과한 것은 구조적 판정·근거 연결의 소프트웨어 테스트이며, 실제 사주의 격국 성립이나 명리학 전문가의 일치도를 검증하는 것은 아니다.

**R-011 완료 전제**: 전문가가 격국별 원전 사례, 경계 사례, 파상신 및 대체 구응 사례를 검토하고 모든 결정 조건을 승인한 후 운영용 규칙을 활성화한다.

## 9. 고객에게 보여줄 문장 정책

## 2. 결정 순서 및 상위 차단 조건

1. **계산·승인 검증**: R-006의 강약 판정값이 전문가 승인 규칙에 의해 확정되었는지 확인. 단지 R-006 *설계 정책을 채택*한 상태로는 불충분.
2. **특수격 선행 검사**: R-009의 결과가 '검토 후보', '특수격 확인', '판정 미완료'라면 일반 억부 후보 자동 선정을 중단하고 `special_review` 반환. `cleared`는 신뢰된 서버 규칙과 근거가 있어야 한다.
3. **중화·판단유보 처리**: 승인된 `balanced`도 '수·목 등 특정 오행을 억부용신으로 지명해야 한다'는 충분한 근거가 아니다. R-012는 자동 추천을 하지 않는다.
4. **오행 후보 생성**: 강약에 따라 지원/조절 후보군을 만든다.
5. **지배 세력 상황별 예비 우선 검토**: 승인된 맥락일 때에만 일부 후보를 먼저 검토한다. 이것은 정답 판정이 아니다.
6. **격국 및 상신 충돌 확인**: '격국용신과 오행이 다르다'는 것만으로 충돌이 아니다. 실제 성립·보호 기능을 손상하는 *구체적인 작용 경로*가 있어야 한다.
7. **R-013/014로 전달**: 조후·통관·병약과 상충하면 공존하는 후보와 충돌 근거를 보존한다. 단일 용신 최종 결정은 실행하지 않는다.

## 4. 원국 상황별 별도 심사

## 5. 격국용신·상신과의 충돌

다음 세 가지를 구분한다.

- `different_purpose`: 억부 후보와 격국의 중심 오행이 서로 다름. 충돌이라는 결론 아님.
- `possible_harm`: 승인되지 않은 제약/합화/파상신 경로. 양측의 후보 및 미확정 사유 보존.
- `confirmed_harm`: 승인된 상호작용 규칙과 증거가 실제로 격국 중심·상신의 기능을 손상함. 그 *후보*에만 손상 표시, 다른 후보까지 삭제하지 않음.
- `cleared`: 구체적으로 명시된 특정 대상에 대한 검토 완료. 원국 전체가 안전하다는 증거가 아님.

실제 손상 검토가 필요하지만 R-010·R-011이 후보 수준이라면 `R-014`에서 최종 조정한다. 격국용신, 상신, 억부용신, 조후용신을 덮어쓰지 않는다.

## 6. 보수적 상태값과 출력

- `strength_review`: R-006 승인되지 않음/중화·미정 -> 후보 없음.
- `special_review`: R-009 종격/가종/전왕 등의 검토가 미완료 -> 일반 후보 없음.
- `candidate_review`: 강약 확정·특수격 해소 후 오행 후보는 있으나 지배세력 검증 없음.
- `await_R014`: 지원/제어 후보와 맥락이 생성되었고 R-013/014 검사 필요.

후보별로 `family`, `role`, `preference`, `status`, `comparisonIds`, `evidenceIds`, `limitations`을 저장한다. `fuyiYongshen`과 `singleRecommendedElement`는 `null`, `finalApproval`은 항상 `false`이다.

## 7. 운영 승인과 데이터 계약

- `Strength` 결과는 `R-006`의 *검증된* 승인 결과만 신뢰한다.
- `R-009` 특수격 `cleared`는 기본값이 아니며, 전문 규칙의 불성립 검증이 완료되어야 한다.
- R-011의 상신·격국 결과는 실제 구현상 아직 후보 수준이므로 운영용 확정값처럼 가정하지 않는다.
- `trustedRuleIds`가 예제 코드에서 배열로 주어져도 **실서비스에서는 클라이언트가 마음대로 줄 수 없도록 서버의 승인 레지스트리에서 서명 또는 권한 검증**을 수행해야 한다.
- `approvedByRule`과 `evidenceIds`는 필수. 중복 비교 대상, 미승인 완료 신호, 종격 미해결 상태를 검증한다.
- 소스·규칙·달력 버전, 모델 버전, 원국 ID, 승인 이력, 원국 계산 정확도도 원장에 기록한다.

12. 같은 원국 및 버전이면 동일 결과 생성.

확인된 이견 사례: **甲日 酉月**에서 일부 2차 표는 庚·丁·丙 순서이나 확인한 본문은 **丁 먼저, 丙 다음, 庚 그다음**이라고 명시한다. 따라서 표에 천간을 나열하는 순서 자체가 승인된 우선순위를 뜻하지 않는다.

## 4. R-013-A 조후 분석 규칙

1. `climate_diagnosis`는 `cold_excess`, `heat_excess`, `dry_excess`, `damp_excess`, `balanced_candidate`, `unknown` 가운데 필요한 진단을 *독립 근거*로 등록한다. 한난·조습을 단일 양의/음의 점수로 합치지 않는다.
2. 위 120 색인에서 해당 일간·월지의 원전 대조 상태를 가져온다.
3. 원문에서 특정 천간을 *기후 조절*과 연결했다는 근거와 *격국 성립/재제화* 등 다른 목적으로 쓴 근거를 구분한다.
4. 후보 천간이 투출·지장간 존재·통근·간합·극제에 의해 어떤 상태인지 검사한다. 후보가 **없다는 사실**과 **그 기운이 나쁘다는 주장**도 구별한다.
5. 종격/억부/격국/조후 후보의 **목적**은 별개로 기록한다.
6. 미승인 조후 진단, 2차 요약 단독 사용, 시간 구간 이견, 미해결 합충, 원국 오류는 자동 용신 확정을 금지한다.
7. 실제 조후의 '한난조습'은 현실의 건강이나 성격에 대한 과학적 진단이 아니다.

## 5. R-013-B 통관 분석 규칙

《滴天髓闡微》 「通關」 원문은 木土→火, 火金→土, 土水→金, 金木→水의 연결을 예시로 들고, 거리·형충·차단을 함께 논한다. 아래의 다섯째 水火→木은 **오행 생극표에서 연역한 현대적 형식적 확장**이며 동일 문장에 원문 그대로 열거된 것이 아니다.

| 극제 방향 | 이론적 연결 요소 | 생조 경로 | 비고 |
|---|---|---|---|
| 木克土 | 火 | 木→火→土 | 고전 열거 |
| 火克金 | 土 | 火→土→金 | 고전 열거 |
| 土克水 | 金 | 土→金→水 | 고전 열거 |
| 金克木 | 水 | 金→水→木 | 고전 열거 |
| 水克火 | 木 | 水→木→火 | 오행 생극에서 파생한 후보 |

**성립 검사:** (A) 실제 극제 관계가 원국에서 확인되는가, (B) 매개 오행이 천간/지장간에 존재하는가, (C) 그 매개가 합거·극제·장애로 무력화되지 않는가, (D) 연결 경로의 자리·노출·통근이 고전의 의도에 부합하는가, (E) 다른 병과 격국의 상신을 훼손하지 않는가.

**불성립/유보:** 극제 상대가 존재하지 않음, 매개 기운이 실제로 없음, 매개는 있으나 작용 검증 부족, 원국 합화·충돌 미확정. **수생목이라는 관계가 존재한다고 통관이 성립하는 것이 아니다.**

## 6. R-013-C 병약 분석 규칙

《神峰通考》 「病藥說類」는 명식에서 문제가 되는 요소(病)를 찾고 그 문제를 해소하는 요소(藥)를 논한다.

- `disease_id`: 의료상 질병이 아니라 **명리학의 구조적 장애 ID**. 사용자에게 의료·질환 진단처럼 표현하지 않는다.
- `disease_target`: 손상되는 격국 요소, 상신, 식신 등 실제 대상
- `harmful_actor_id`: 손상을 발생시키는 실제 천간·지장간·관계 ID
- `medicine_action`: `control_harm`, `channel`, `protect_core`, `combine_away` 등 **서로 다른 기제**
- `medicine_actor_id`: 약에 해당하는 실제 요소 (부재 시 이론적 후보만)
- `review_status`: 병 자체의 검증, 약의 존재, 약의 실제 효력, 다른 대상에 미치는 부작용을 각각 분리

**예시:** 甲木 일간의 食神 丙火가 偏印 壬水의 극제를 받는 것으로 검증된 경우, 壬의 방해를 제어하는 戊土(財)를 병약 후보로 탐지할 수 있다. 그러나 戊가 없거나 합거되거나 구조적으로 유해할 경우 효과를 확정하지 않는다. 병약은 반드시 `disease_id → medicine_candidate_id`로 연결한다.

**거짓 양성 방지:** 재극인, 식신제살 등 관계 이름의 존재는 병이 아니다. 해당 격국에서 그 관계가 실제로 해로운지를 먼저 승인해야 한다. 의학적 병과 전혀 무관하다.

## 7. 학파 차이 / 격국·억부 충돌

- 《穷通宝鉴》은 월별 조건부 취용에 초점을 둔다. 이 중 특정 천간은 조후보다는 제살·윤택·도구 역할일 수 있으므로 모든 취용 천간을 조후용신이라고 이름 붙이지 않는다.
- 《滴天髓》 통관의 방향은 생극의 매개 연결이지만 실제 생극 작용의 성립을 더 검토해야 한다.
- 《神峰通考》 병약은 해결해야 하는 문제가 먼저 존재한다는 조건에 매여 있다. 격국 성립 문제의 구응(R-010)과 중복할 수 있으므로 동일 원천 ID를 연결한다.
- 《子平真诠》의 格局用神은 R-011에서 별도 관리한다. R-012 억부 결과, R-013 조후·통관·병약 결과를 **동일한 용신으로 일괄 덮어쓰지 않는다.**
- 甲冬月을 가정하면 억부론에서 水·木 후보, 조후론에서 火 후보가 동시에 생성될 수 있다. '어느 쪽이 진짜인가'는 R-014의 목적별 충돌 검토 대상이며 숫자 다수결로 결정하지 않는다.

## III. '우선순위'의 정확한 정의

### 1. 평가·승인의 순서 (절대 비교 불가능한 공통 필수 관문)
1. 만세력 원국/절입/시간대의 정합성 및 모든 룰 버전의 일치 여부 검증. 불일치 시 `blocked`.
2. 각 상위 모듈의 **판정 상태** 검증. `candidate`를 `approved`로 올리지 않음.
3. R-009 종격·가종이 미해결이면 일반 억부 강약 조절의 자동 확정 중지.
4. 격국 중심, 상신, 조후 문제, 통관 edge, 병약 issue가 각각 유효한지를 해당 도메인 기준으로 검토.
5. 유효한 조절 후보가 다른 도메인의 보호 대상에 실제로 손상을 주는지 교차 도메인 비교.
6. 해결되지 않은 손상과 완화·대체 경로 확인. 단일 기능 손상으로 명식 전체 판단을 확정하지 않음.
7. 독립 결론의 유지, 조건부/유보 사유 생성. **운영 승인을 받은 결정 규칙이 없으면 최종 하나로 고르지 않음.**

### 2. 목적별 우선순위 (서로 다른 질문에 다른 답을 유지)
- **'격국은 무엇인가'**에는 R-007~R-011을 주 판단 체계로 적용. R-012가 격국을 덮어쓰지 않는다.
- **'강약 조절은 무엇인가'**에는 R-006·R-009·R-012를 적용. R-011의 격국 용신을 그대로 억부 후보로 옮기지 않는다.
- **'한난조습 조절은 무엇인가'**에는 R-013 월령 조건을 적용하되 원전과 현대 요약, 조건, 실제 조후 상태를 구분한다.
- **'이 충돌을 연결하는 매개는 무엇인가'**에는 R-013 통관의 특정 극제 관계와 매개를 사용한다.
- **'이 문제의 해결은 무엇인가'**에는 R-010 손상 ID와 R-013 병약 ID를 맞춰 사용한다.

### 3. 이론 간 최상위 서열 없음
'격국 1순위→조후 2순위→억부 3순위' 혹은 그 반대의 보편적인 자동 서열 **미채택**. 사용자에게 '한 가지 용신'이 필요하면 먼저 선정 목적을 지정하고, 목적별 승인 조건을 모두 통과해야 한다. 목적이 다른 서로의 '값'이 달라도 그 자체는 충돌이 아니다.

## IV. 충돌 종류, 판정 및 해결 방식

| 유형 | 예시 | R-014 처리 |
|---|---|---|
| `DIFFERENT_PURPOSE` | 격국 중심 정관(金), 억부 후보 水 | 정상적으로 동시 보존, 충돌로 집계하지 않음 |
| `SAME_ELEMENT_DIFFERENT_ROLE` | 억부의 水와 통관의 水 | 우연한 동일 원소. 서로의 효력을 입증하는 투표 아님 |
| `POTENTIAL_MECHANISM_HARM` | 신강 갑목의 火(식상) 후보가 정관 辛을 극할 가능성 | 관계 후보, 실제 효력 미확정; 검토 필요 |
| `CONFIRMED_THEORETICAL_HARM` | 승인된 격국 제약 규칙에서 해당 작용이 성립 | 해당 **특정** 대상에 대한 손상 기록, 후보 재심사 |
| `RESCUED_TARGET_ONLY` | 인성이 상관을 제어해 정관 보호, 다른 관살혼잡 미해결 | 해당 손상 ID만 완화. 나머지 유지 |
| `CONDITIONAL_SOURCE_CONFLICT` | 《궁통보감》 원전 vs 2차 요약의 순서 차이 | 판본·해석·월내 구간 확인 전 유보 |
| `SPECIAL_FOLLOW_CONFLICT` | 종격 후보와 일반 억부용신 후보 | 종격 성립 여부 검증 전 일반 억부 확정 불가 |
| `INSUFFICIENT_VALIDATION` | 월령 분일·강약·합화 미해결 | `pending_review` 또는 `blocked` |

**규칙 R014-004 | 충돌은 '다른 오행'이 아니라 '동일 대상으로 향하는 실제 유해한 작용'으로 정의한다.**

**규칙 R014-005 | 손상 상태:** `unknown` → `potential_harm` → (`confirmed_harm` / `cleared`). 고전 이론 내부의 승인된 규칙으로 '확인'했다는 뜻이지 실제 인생 사건의 인과 관계 검증이 아니다.

**규칙 R014-006 | 구응의 범위:** `obstruction_id`마다 구응 ID를 연결하고, 하나의 구응이 관계없는 다른 손상을 제거하지 못하게 한다.

**규칙 R014-007 | 대체 가능성:** 상신 A의 손상이 있어도 다른 완전한 성격 경로 B가 있는 경우, 전체 격국의 성패는 R-010의 재심사를 통해서만 변경한다.

## V. 판단 유보 / 차단 정책

**즉시 차단 (`blocked`):** 원국이 미검증, R-001~R-013 manifest 누락/버전 불일치, 선행 결과의 일간/월령 불일치, 불법적인 승인 ID, 신뢰하지 못할 출처의 교차 손상 '확정' 신호. 일부 사례는 예외를 throw 하여 호출 자체를 실패시킨다.

**판단 유보 (`pending_review`):** 적법한 계산 후보이나 실제 효력 또는 R-006/R-009/R-010/R-011의 최종 승인 부재, 《궁통보감》의 원전/조건/서열 미검증, 통관 매개 존재하나 효력 미검증, 병 자체가 후보, 사령·토월·합화 분쟁, 최종 목적 지정 부재.

**충돌 검토 (`conflict_review`):** 의미 있는 손상 `potential_harm` 또는 `confirmed_harm`가 **명시적인 두 후보 ID 사이**에서 보고됨. 금과 화가 다르다는 이유만으로 해당 상태로 바꾸지 않는다.

**확정 (`approved`):** R-014-DRAFT-1에서는 **지원하지 않음**. R-006~R-013의 상위 결과가 기본 정책 승인만 있고 실제 운영용 확정 판단이 없으므로 도메인별 승인·필수성·기능 충돌 조건이 추가될 때까지 최종 용신은 `null`이다.

## 3. 만세력 엔진 정확성

### 3.1 입력 정책
- 사용자가 입력한 출생지의 **당시 현지 법정시**와 time-zone ID(`Asia/Seoul` 등)를 수집한다. 현재 단순 `UTC+09` 고정은 금지.
- 음력인 경우 윤달 여부를 명시하고 양력으로 변환한다. 국적이나 현재 거주국으로 출생지/time-zone을 추론하지 않는다.
- 모호하거나 존재하지 않는 현지시각(DST fold/gap)은 사용자가 선택하거나 검증 가능한 출생기록을 요구하고, 임의로 한 시간을 선택하지 않는다.
- 23시 야자시 및 일주 날짜 변경, 진태양시 사용 여부는 명리학 **정책**으로 구분한다. astronomical UTC 정규화와 혼용하지 않는다.
- 진태양시 적용 여부는 임의로 선택하지 않고, 경도·균시차·표준시 차이·기준 경선을 가진 별도 정책 버전으로 남긴다.

### 3.2 절기와 간지
- **년주 경계:** 입춘을 사용할지 기타 경계를 사용할지 서비스 정책과 출처를 명시. 기본안은 입춘 절입 순간.
- **월주 경계:** 12개의 절(寅월 입춘, 卯월 경칩, 辰월 청명, 巳월 입하, 午월 망종, 未월 소서, 申월 입추, 酉월 백로, 戌월 한로, 亥월 입동, 子월 대설, 丑월 소한)을 타임스탬프로 저장. 24절기 전체의 중기와 혼동하지 않는다.
- `start <= birth_instant < next_start`를 기본 구간 정책으로 채택(경계 포함 방향 명시).
- **일주:** 알려진 기준일과의 절대일수 차를 사용하고, 달력 개혁과 경계 정책을 버전 관리.
- **시주:** 시간지·일간에서 시간간으로의 연결을 고정 표 및 전수 테스트; 시각 불명 시 복수 결과.
- 한국천문연구원 특일 API는 24절기의 **날짜 확인용**으로 활용할 수 있으나, 문서에서 시간·분·초를 제공하는지 별도 확인하기 전에는 **정밀 절입 시각 공급원**으로 인증하지 않는다. 정확한 절입 시각은 전문 천문력 또는 신뢰 가능한 천문 계산 엔진으로 확보하고 독립 비교한다.
- 천문 시간척도 TT/UT·ΔT를 사용한다면 공인 계산 라이브러리의 사용법과 불확실성을 문서화한다.

### 3.3 검증 패턴
- 입춘·경칩·청명 등 12절 각각 `T-1초, T, T+1초` 3개 경계 케이스; 전 연도군에 대해 독립 기준자료 비교.
- 1908·1912·1954·1961·1948~1960 일부·1987~1988의 한국 시간대/DST 이력; 각 연도 실재 규칙은 tzdb/별도 기록과 교차검증.
- 하루 경계 22:59:59 / 23:00:00 / 23:59:59 / 00:00:00 및 DST 애매한 시각 처리.
- 2월 29일, 윤달, 연도 음양력 변환, UTC 경계, 해외 출생, 출생시간 불명, 소수 경도.
- 권장 검증치(초안): 검증된 기준 시각과 차이 ≤60초; 절입 경계로부터 오차 허용폭 내의 입력은 계산을 유보. 이 수치는 명리학 원전 상수가 아니라 QA 시작 목표이며 실제 천문력의 정확도에 맞춰 재승인한다.
- 기준시각 없는 기대 간지나 실존 명식을 테스트에 꾸며 넣지 않는다.

## 4. 전문가 검증 절차

### 4.1 판정 데이터셋
기준 명식은 합성 테스트(수학적 불변식)와 실제 고전/전문가 명식(학파별 판단)을 별도 보관한다.

권장 초기 규모는 계산 경계 500건 이상, 일반 해석 사례 200건, 이견·특수격 경계 100건의 **출시 전 검증 목표안**이다. 이 숫자는 통계적 정확성을 입증하는 기준이 아니라 프로젝트가 선택할 QA 출발점이다.

### 4.2 전문가 판정
- 명리학 전문가 최소 2명 독립 검수, 충돌 사례는 제3의 심사자가 원전 출처·판본과 조건을 비교.
- 전문가에게 최종 정답만 받지 말고 **근거 ID, 사용 학파, 검토한 반례, 미확정 이유**를 필수로 받는다.
- 120개 《궁통보감》 조합은 개별 원문/주용/보조/조건/상순·하순/판본을 검수한다. 120개를 단일 표로 옮겼다고 검수 완료 아님.
- 합의율을 기록하되 다수결로 격국을 확정하지 않는다. 이견은 출처와 정책 차이로 관리.
- 검수자는 릴리스 승인 코드를 수정하는 사람과 분리하여 서명. 생산 운영 승인 이력 불변 보관.

### 4.3 승인 범위
`policy_accepted` → `source_checked` → `implemented` → `unit_verified` → `expert_reviewed` → `integrated` → `release_approved`. 중간 단계를 건너뛰지 않는다. 승인 범위는 '천문 계산', '십성 분류', '신강신약 후보', '최종 용신' 등 구체적인 claim type 단위.

## 5. R-015 릴리스 게이트

| 게이트 | 차단 조건 | 승인 문서 |
|---|---|---|
| G0 입력/개인정보 | 불명확한 시간대, DST gap, 사용자 동의·삭제 절차 없음 | Input Policy vN |
| G1 천문 계산 | 절입 시각 불명, 시각 없는 날짜 API만 사용, 기준 명식 불일치 | Almanac QA Report |
| G2 기초 규칙 | R001~R009 타입·버전·근거 불일치, 미검증 필수 규칙 | Dependency Audit |
| G3 해석 | 승인되지 않은 격국·강약·용신을 확정 설명 | Claim Whitelist |
| G4 전문가 | 문헌·명식 검수와 충돌 결론 미완료 | Expert Sign-off |
| G5 기술·보안 | RLS/grants 실패, 크레딧 중복, API 키 유출, 결제 우회 | Security/Commerce QA |
| G6 운영 | 백업·복구 훈련 미완료, 배포/롤백 계획 없음 | Release Checklist |

출시 상태는 `NO_GO`(모두 차단), `LIMITED_GO`(특정 기능만), `GO`(해당 상품 기능 승인)이다. **한 상품이 GO라는 것은 다른 상품의 GO를 의미하지 않는다.** 

기본 캐릭터는 `R-001+R-002+승인된 캐릭터 매핑`, 필요한 경우 R-003 등을 상품 계약(`requiredRules`)에 추가한다. 기본사주/연애운은 표시하는 claim에 따라 R-001~R-014 중 의존 규칙을 선언한다. 월간 상품 권한·5개 역년 세운의 연속 구간 같은 유료 기능 정책 역시 서버 측 시험 항목에 포함한다.

## 6. Lovable + Supabase 권장 데이터 흐름

```text
Lovable UI
  └── Supabase Auth 로그인 / 입력 검증 / 상품 설명
        └── Edge Function (JWT 검증, product contract, rate-limit)
              ├── Almanac deterministic service (절입 UTC, zone, day/hour)
              ├── R001..R014 rules + immutable approval registry (SERVER)
              ├── R015 gate + redacted evidence
              ├── credit/payment server-only atomic transaction
              └── LLM receives ONLY approved claims; generated text schema validated
                    └── analysis_runs (owner RLS) → Lovable UI
```

**브라우저가 보내면 안 되는 필드:** `approvedByRule`, `trustedRuleIds`, `ruleReleaseDigest`, `price`, `creditBalance`, `isPaid`, `finalGeju`, `finalYongshen` 등. 서버 재계산/조회.

### 6.1 DB 핵심 테이블
- `private.rule_releases`: 불변 해시, 승인자, 전문가 서명, 원전 수정 이력 (사용자 접근 금지).
- `public.analysis_runs`: 소유자, 차트의 비식별 HMAC, 사용된 규칙 manifest, 유효성·해석 JSON. 개인 출생기록 평문 저장은 피한다.
- `public.credit_wallets`: 서버만 수정하는 원장 잔액.
- `public.credit_ledger`: 서버만 추가, 소유자만 읽기, 사용자+idempotency_key UNIQUE.
- 유료 콘텐츠는 결제/크레딧 지출 전 읽기 가능한 곳에 렌더링·저장하지 않는다. 상품 이용 권한은 서버에서 판정한다.

### 6.2 RLS·권한 검증
- 모든 `public` 노출 테이블에 RLS 활성화, anon/authenticated grants를 필요한 동작으로 제한.
- User A는 A의 분석/원장만 읽기; User B 데이터는 select/insert/update/delete 우회 접근을 모두 차단.
- `service_role` 또는 신규 secret key는 브라우저에 노출하지 않는다.
- SECURITY DEFINER 함수는 schema 접근/EXECUTE grants, search_path, 내부 소유권 검사를 명시한다.
- Edge Functions에서 JWT 서명·주체·권한을 검증한 다음 관리자 클라이언트를 사용한다. 서비스 Role 키와 사용자 Bearer 헤더를 혼용하지 않는다.
- Lovable 기본 보안 스캔과 SQL 기반 RLS·grants·pgTAP·실제 두 사용자 통합 테스트를 함께 수행한다.

### 6.3 결제·크레딧·추천 보상
- 지출, 지급, 환불은 중복되지 않는 idempotency key로 처리한다.
- 동시 결제/동시 차감은 wallet row lock + 하나의 DB 트랜잭션으로 처리해 음수 잔액·이중 지출 방지.
- 결제 웹훅은 서명과 서버 측 결제금액/상품/상태 조회를 검증 후 반영한다.
- 추천인 적립은 유효 신규 사용자 검증, 자기 추천 방지, KST 날짜·월 한도, 이중 가입, 반환/취소, replay 이벤트 테스트가 필요하다.
- 클라이언트가 천문 계산이나 LLM의 cost 기록과 무관하게 결제 상태를 승인할 수 없게 한다.

## 7. LLM 안전한 출력 계약

LLM 입력에는 `claim_id`, `rule_release_digest`, `claim_status=approved`, `support_evidence_ids`, `explanation_allowed`, `uncertainties`만 전달. 후보는 '후보/검토 중'이라는 맥락에서만 설명하고 결론에 쓰지 않는다.

LLM 출력은 JSON schema, allowed claim IDs, 금지 단정 표현(예: 확정적 질병/사망/재산 예언), prompt injection, 개인정보 재노출, 테스트 패턴을 검사한다. 정형화된 분석값 변경은 항상 차단한다.

## 8. 필수 테스트 매트릭스

1. 정상/경계/오류 시각별 월주·년주·시주·일주 일관성.
2. R-003 A/B 분일이 다른 사령이라도 확정 판단으로 누락되지 않는지.
3. R-004 통근/생조 분리; R-005 일간 비견 중복 오류 방지.
4. R-006↔R-009 순환·충돌; 종격 후보 있을 때 R-012 억부 자동 차단.
5. R-007 본기 vs R-008 투간·회국 간 모순, R-010 partial rescue.
6. R-011 상신과 R-012 억부 및 R-013 조후 용어/타입 혼동 방지.
7. R-014 이론별 후보 숫자 투표와 미승인 `finalYongshen` 차단.
8. 임의 승인 ID, manifest version mismatch, cross-user chart swap 차단.
9. 결제 웹훅 중복·취소·부분환불, 잔액 부족·레이스, 추천 한도.
10. 비회원 체험과 회원가입 연동 시 다른 사용자의 유료 결과·차트 노출 방지.
11. 이메일/생년월일/결제정보가 로그·LLM 프롬프트에 불필요하게 노출되지 않는지.
12. 장애 상황에서 롤백/재시도/중복 청구/결과 기록이 일관적인지.

- 천문 계산 담당: 타임존·절입·전환 케이스 서명
- 백엔드 보안 담당: RLS·키·원장·권한 서명

릴리스 생성: immutable manifest digest + Git revision + migration checksum + 테스트 보고서 + 서명. 기존 결과에는 사용된 릴리스 버전을 붙이고, 새 규칙으로 재계산하더라도 과거 원본 결과를 묵시적으로 덮어쓰지 않는다.

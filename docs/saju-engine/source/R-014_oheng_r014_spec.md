# 오행 친구들 · 명리학 해석 기준서 v1.0
## R-014 — 格局·扶抑·調候·通關·病藥用神 종합·충돌·근거 추적

**규칙:** `R-014-DRAFT-1` | **상태:** 사용자 검토·채택 대기; 운영용 최종 용신 선정 불가  
**선행:** R-001~R-013의 계산 정책, 후보 결과, 각각의 *검증 상태*  
**대상:** Lovable/Supabase의 백엔드(서버 권한)에서 실행하는 결정적 통합/감사 모듈  
**비대상:** 원국 재계산, R-006 강약의 미완성 부분 임의 완성, R-009 종격 확정, R-013 월별 120항목의 전수 원전 검증, 미래 사건의 사실 예측.

> 핵심: 용신이라는 이름이 동일하다고 선정 *목적*도 동일한 것은 아니다. 격국 중심·상신·억부·조후·통관·병약을 다른 네임스페이스에서 비교하고, 실제 작용·손상 여부가 승인되기 전에는 단일 용신으로 환원하지 않는다.

## II. 다섯 분석 도메인의 타입 계약

| ID | 비교 가능한 값 | 역할 | 반드시 구분해야 할 사실 |
|---|---|---|---|
| `GEJU` | 격국 후보 ID, 상신 actor ID | 격국 구조의 중심·성립 도우미 | `pattern_core`는 오행 선호도가 아님 |
| `FUYI` | 五行 및 해당 일간과의 십성 범주 | 강약 조절 후보 | R-006 승인 및 특수격 해소 필요 |
| `CLIMATE` | 일간+월령+원전 항목+천간의 **역사적 언급** | 계절/조건별 조절 가능성 | R-013 원전 언급은 120개 완전 승인 데이터가 아님 |
| `TONGGUAN` | 극제 edge ID+매개 五行+actor ID | 극제 관계의 중개 | 매개 오행의 존재 ≠ 통관 효과 성립 |
| `BINGYAO` | issue ID+problem actor+remedy actor/五行 | 특정 병의 해결 후보 | 병이 승인되지 않았다면 약도 불확정 |

**규칙 R014-001 | 타입 보존**: `pattern`·`stem`·`element`·`actor`를 명시하며 임의 형변환 금지. 격국 중심을 `金` 한 글자로 치환한 뒤 억부와 투표하지 않는다.

**규칙 R014-002 | 상태 보존**: `historical_reference`, `structural_candidate`, `conditional_candidate`, `requires_review`를 관리하며, 원전 대조 상태를 자동 승인 상태로 변환하지 않는다.

**규칙 R014-003 | 근거 추적**: 후보마다 원본 원국 ID, 상위 규칙 버전, actor/issue/obstruction ID, 실제 계산 근거, 판본·규칙의 식별자를 기록한다. 동일 지장간이 여러 규칙을 통과했다는 이유로 독립적인 추가 증거로 합산하지 않는다.

## III. '우선순위'의 정확한 정의

### 1. 평가·승인의 순서 (절대 비교 불가능한 공통 필수 관문)
1. 만세력 원국/절입/시간대의 정합성 및 모든 룰 버전의 일치 여부 검증. 불일치 시 `blocked`.
2. 각 상위 모듈의 **판정 상태** 검증. `candidate`를 `approved`로 올리지 않음.
3. R-009 종격·가종이 미해결이면 일반 억부 강약 조절의 자동 확정 중지.
4. 격국 중심, 상신, 조후 문제, 통관 edge, 병약 issue가 각각 유효한지를 해당 도메인 기준으로 검토.
5. 유효한 조절 후보가 다른 도메인의 보호 대상에 실제로 손상을 주는지 교차 도메인 비교.
6. 해결되지 않은 손상과 완화·대체 경로 확인. 단일 기능 손상으로 명식 전체 판단을 확정하지 않음.
7. 독립 결론의 유지, 조건부/유보 사유 생성. **운영 승인을 받은 결정 규칙이 없으면 최종 하나로 고르지 않음.**

### 2. 목적별 우선순위 (서로 다른 질문에 다른 답을 유지)
- **'격국은 무엇인가'**에는 R-007~R-011을 주 판단 체계로 적용. R-012가 격국을 덮어쓰지 않는다.
- **'강약 조절은 무엇인가'**에는 R-006·R-009·R-012를 적용. R-011의 격국 용신을 그대로 억부 후보로 옮기지 않는다.
- **'한난조습 조절은 무엇인가'**에는 R-013 월령 조건을 적용하되 원전과 현대 요약, 조건, 실제 조후 상태를 구분한다.
- **'이 충돌을 연결하는 매개는 무엇인가'**에는 R-013 통관의 특정 극제 관계와 매개를 사용한다.
- **'이 문제의 해결은 무엇인가'**에는 R-010 손상 ID와 R-013 병약 ID를 맞춰 사용한다.

### 3. 이론 간 최상위 서열 없음
'격국 1순위→조후 2순위→억부 3순위' 혹은 그 반대의 보편적인 자동 서열 **미채택**. 사용자에게 '한 가지 용신'이 필요하면 먼저 선정 목적을 지정하고, 목적별 승인 조건을 모두 통과해야 한다. 목적이 다른 서로의 '값'이 달라도 그 자체는 충돌이 아니다.

## IV. 충돌 종류, 판정 및 해결 방식

| 유형 | 예시 | R-014 처리 |
|---|---|---|
| `DIFFERENT_PURPOSE` | 격국 중심 정관(金), 억부 후보 水 | 정상적으로 동시 보존, 충돌로 집계하지 않음 |
| `SAME_ELEMENT_DIFFERENT_ROLE` | 억부의 水와 통관의 水 | 우연한 동일 원소. 서로의 효력을 입증하는 투표 아님 |
| `POTENTIAL_MECHANISM_HARM` | 신강 갑목의 火(식상) 후보가 정관 辛을 극할 가능성 | 관계 후보, 실제 효력 미확정; 검토 필요 |
| `CONFIRMED_THEORETICAL_HARM` | 승인된 격국 제약 규칙에서 해당 작용이 성립 | 해당 **특정** 대상에 대한 손상 기록, 후보 재심사 |
| `RESCUED_TARGET_ONLY` | 인성이 상관을 제어해 정관 보호, 다른 관살혼잡 미해결 | 해당 손상 ID만 완화. 나머지 유지 |
| `CONDITIONAL_SOURCE_CONFLICT` | 《궁통보감》 원전 vs 2차 요약의 순서 차이 | 판본·해석·월내 구간 확인 전 유보 |
| `SPECIAL_FOLLOW_CONFLICT` | 종격 후보와 일반 억부용신 후보 | 종격 성립 여부 검증 전 일반 억부 확정 불가 |
| `INSUFFICIENT_VALIDATION` | 월령 분일·강약·합화 미해결 | `pending_review` 또는 `blocked` |

**규칙 R014-004 | 충돌은 '다른 오행'이 아니라 '동일 대상으로 향하는 실제 유해한 작용'으로 정의한다.**

**규칙 R014-005 | 손상 상태:** `unknown` → `potential_harm` → (`confirmed_harm` / `cleared`). 고전 이론 내부의 승인된 규칙으로 '확인'했다는 뜻이지 실제 인생 사건의 인과 관계 검증이 아니다.

**규칙 R014-006 | 구응의 범위:** `obstruction_id`마다 구응 ID를 연결하고, 하나의 구응이 관계없는 다른 손상을 제거하지 못하게 한다.

**규칙 R014-007 | 대체 가능성:** 상신 A의 손상이 있어도 다른 완전한 성격 경로 B가 있는 경우, 전체 격국의 성패는 R-010의 재심사를 통해서만 변경한다.

## V. 판단 유보 / 차단 정책

**즉시 차단 (`blocked`):** 원국이 미검증, R-001~R-013 manifest 누락/버전 불일치, 선행 결과의 일간/월령 불일치, 불법적인 승인 ID, 신뢰하지 못할 출처의 교차 손상 '확정' 신호. 일부 사례는 예외를 throw 하여 호출 자체를 실패시킨다.

**판단 유보 (`pending_review`):** 적법한 계산 후보이나 실제 효력 또는 R-006/R-009/R-010/R-011의 최종 승인 부재, 《궁통보감》의 원전/조건/서열 미검증, 통관 매개 존재하나 효력 미검증, 병 자체가 후보, 사령·토월·합화 분쟁, 최종 목적 지정 부재.

**충돌 검토 (`conflict_review`):** 의미 있는 손상 `potential_harm` 또는 `confirmed_harm`가 **명시적인 두 후보 ID 사이**에서 보고됨. 금과 화가 다르다는 이유만으로 해당 상태로 바꾸지 않는다.

**확정 (`approved`):** R-014-DRAFT-1에서는 **지원하지 않음**. R-006~R-013의 상위 결과가 기본 정책 승인만 있고 실제 운영용 확정 판단이 없으므로 도메인별 승인·필수성·기능 충돌 조건이 추가될 때까지 최종 용신은 `null`이다.

## VI. 데이터 모델 / API

- 입력: `R011Result`, `R012Result`, `R013Result`, canonical chart ID, `R001..R013` manifest, 서버 확인한 정책 레지스트리, 교차 도메인 review edges.
- 출력: `recommendations` (method+scope+typed value+trace+conditions+blockers), `findings` (explicit pairwise review), `methodSummaries`, `reviewReasons`, `status`.
- `finalYongshen`, `singleBestElement`, `finalGeju`: 현 단계에서 모두 `null`; `finalApproval:false`.
- ID 문자열은 안전한 구조화 키 또는 canonical encoding 사용. 동일 actor의 지장간 근거를 여러 메서드에서 발견했으면 동일 node id를 유지.
- DB 권한: Supabase Edge Functions 등 서버측에서 선행 결론과 승인 규칙을 로드; 브라우저에서 보낸 `validatedByServer:true`만 믿으면 안 된다.
- 보안 추가 구현: 원국 ID와 선행 결과의 불변 스냅샷/해시, 승인 정책의 revision·signature, 읽기권한 분리, 문헌 원문 교감 레코드, 스냅샷 갱신시 재평가.
- 캐시 키 예시: `chart_hash + R001..R014_policy_hashes + primary_sources_revision + interpreter_version`.

## VII. 설명 가능한 결과 예시 (가상적, 실제 원국의 승인 해석이 아님)

甲일간·酉월의 분석에서
- R-011: 정관격 중심 후보 `辛`, 인성 상신 후보 `癸` (구응 효과 미확정)
- R-012: 신강이라고 **가정**한 테스트에서 火·土·金 후보
- R-013: 《궁통보감》의 甲酉 역사적 언급 `丁·丙·庚` (120항목 전수 검증 미완료), 金克木을 水로 잇는 통관 후보

**출력 메시지 규칙:** “격국 분석에서는 정관격 후보를 검토합니다. 강약 조절 분석에서는 火 등의 후보가 존재하지만 정관에 대한 극제 가능성과 실제 작용을 더 검토해야 합니다. 월령 자료에 나타난 丁 등의 글자는 원문상 조건별 언급이며 아직 조후용신 확정값이 아닙니다. 따라서 단일 용신은 선정하지 않았습니다.”

이 문장에는 미래 사건의 실제 예측이나 금전/건강/결혼의 단정이 들어가지 않는다.

- **R014-006** 구응·병약의 `target_id` 범위 제한
- **R014-007** 상신의 필수성·대체 경로 심사
- **R014-008** 종격·가종 후보 미해결 때 일반 억부 확정 금지
- **R014-009** 원문 불완전/분일 이견의 영향이 크면 판단 유보
- **R014-010** 결론이 없는 경우 해당 이유를 출력하고 임의 보완 금지
- **R014-011** 다수결/점수화/가중치 합산 금지
- **R014-012** 서버 승인/불변 원국/재현성 기반의 운영 게이트

## IX. 테스트와 검증

### 코드 단위 테스트
31개 그룹: 5개 독립 영역, 격국 ID와 오행의 타입 구분, 상신 actor ID, 파상신 보류, 억부 후보 보존, 甲酉 원문 **역사적 언급**의 보존, 통관 edge·병약 issue ID, 동일 오행 다수결 금지, 승인된 관계/미승인 관계 차별, 누락·위변조 승인 ID 차단, 13개 manifest 검증, 월령·일간 정합성, 반복호출 재현성, 교차 관계 정렬 일관성.

### 반드시 후속으로 수행할 전문가/통합 테스트
1. 원국의 출생시각/절입 경계·시간대 회귀 검사.
2. 《窮通寶鑑》 원문 120항목 전수 교감: 일간/월령/후보 천간/주용·보조·대체·금기/구간 조건 각기 기록.
3. R-003 A/B 분일·토월 이견이 최종 취격에 실질적인 영향을 주는 경우 유보.
4. R-006 강약·중화의 경계 사례 및 종격·가종의 불성립 조건 검증.
5. R-010 성격·파격·구응, R-011 상신 필수성의 고전 원국 기반 사례 심사.
6. 한 문제에 구응 1개가 있고 다른 문제가 남는 경우 절대 자동 최종화하지 않는 테스트.
7. 격국용신 金과 억부 水를 **불일치라는 이유만으로 충돌**로 판단하지 않는 테스트.
8. 억부 火와 격국 정관 金 사이의 구체적 손상 검사, 보호 인성·합화 유무에 대한 경계 검사.
9. 합법적 후보가 하나도 없을 때와 여러 후보가 존재할 때 모두 `null` 단일 선정 처리.
10. AI가 승인되지 않은 데이터를 한 가지 희용신으로 자동 확정하는 프롬프트 주입 회귀 방지.
11. 원전 차이와 학파 해석 차이를 분리한 승인 검토, 다수결 강행 금지.
12. 사용자 결제 전 알려야 할 주요 분석 제한 항목 검사.

**완료 승인 조건:** 타입스크립트 검증 및 테스트 성공만으로 충분하지 않다. 서버 권한의 정책 승인, R-006~R-013 운영용 판정기의 추가 검증, 120개 원전·조건별 교감, 전문가 해석 검증 및 QA 테스트를 별도로 통과해야 한다.

## X. 운영 단계별 도입

- **Phase 1 (현재):** 후보·근거 추적, 명시적 교차 관계 검사, 보수적 보류 기능을 배포 가능한 기초 모듈로 개발. 실제 용신 확정은 꺼둔다.
- **Phase 2:** R-006/009/010/011의 판정 필요충분조건과 R-013의 원전 교감을 검증하고 도메인별 운영 승인.
- **Phase 3:** 목적별 승인 정책 및 충돌 해결 세칙을 마련해 일부 사주 유형에만 검증된 '용신 선정' 결과를 활성화.
- **Phase 4:** 격국/억부/조후/통관/병약 결과를 함께 설명하는 AI 문장 생성, 리뷰/변경감사/재현성 통계 대시보드.

*명리학 해석 규칙의 일관성에 대한 테스트이며, 특정 사건의 미래 예측력이 과학적으로 입증된다는 뜻은 아니다.*

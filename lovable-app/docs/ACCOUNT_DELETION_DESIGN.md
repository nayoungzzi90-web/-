# 회원 탈퇴 설계 (2026-10-22) — 제안 단계, 실제 삭제는 꺼져 있음

원칙: **사용자 승인 전에는 어떤 회원 데이터도 삭제되지 않는다.** 앱의 탈퇴 기능은 `ACCOUNT_DELETION_ENABLED=true` 일 때만 동작하고 기본은 꺼짐이다. SQL 은 검토용(미적용)이다. 아래 보관 기간·법적 항목은 제가 확인한 것이 아니므로 법무·세무 확인이 필요하다(법적 판단 아님).

## 1. 데이터 목록과 처리(제안)
| 데이터 | 개인 식별 | 탈퇴 시 처리 |
|---|---|---|
| `birth_profiles` (이름·생년월일·출생시간·성별·음력 원본) | 예 | **즉시 삭제** |
| `unlocked_readings` (열람 기록) | 사용자 id | **즉시 삭제** |
| `invite_codes` | 사용자 id | **즉시 삭제** |
| `wallets` (엽전 잔액) | 사용자 id | **삭제**. 남은 엽전은 동의 시 소멸(원장에 `adjust` 기록) |
| `referrals` | 사용자 id | 초대받은 쪽이 탈퇴 → 삭제 / 초대한 쪽이 탈퇴 → 대기 연결은 `skipped(inviter_deleted)` |
| `coin_orders` · `coin_purchases` · `coin_ledger` · `invite_rewards` | **가명**(임의 uuid + PG 결제번호, 이름·이메일 없음) | **남김**(보관 만료일까지) → 만료 후 `purge_retained_records()` 로 삭제 |
| `auth.users` (이메일·로그인) | 예 | 서버가 별도 삭제(Auth admin API) |
| 결제대행사(PG)의 구매자 정보 | 예 | PG 보관 정책에 따름(**우리가 지울 수 없음**) |
| `account_deletions` | 아니오 | 탈퇴 감사 기록(탈퇴일·소멸 엽전·보관 만료일), 개인정보 없음 |

## 2. 구현된 것(미적용·꺼짐)
- SQL `docs/migrations/REVIEW_ONLY/ACCOUNT_DELETION_REVIEW_ONLY.sql`: `delete_member_data`(멱등, 동의 없이 엽전이 남으면 `COINS_REMAIN` 으로 거부하고 아무것도 지우지 않음, 대기 주문 취소) · `purge_retained_records`(만료된 탈퇴자 기록만 삭제) · `account_deletions`. service_role 전용, `search_path` 고정.
- 앱 서버 `account.server.ts` + 서버 함수 `deleteMyAccount`(확인 문구 "탈퇴", DB 삭제 → 계정 삭제 순서, 2단계 실패 시 같은 요청 재시도로 이어서 처리) · `getAccountDeletionStatus`.
- 화면 `/account-delete`(무엇이 지워지고 남는지 안내, 남은 엽전 동의 체크, 확인 문구 입력), 마이페이지 링크.
- 시험: SQL 6개(변이 시험으로 동의 검사·삭제 누락·결제기록 삭제·기간 무시·주문 취소 누락을 실제로 잡는지 확인), 앱 16개(실제 supabase-js 를 가짜 서버에 연결 포함).

## 3. 승인이 필요한 결정(제 제안 → 사용자 결정)
1. **결제·원장 기록 보관 기간**: 제안 5년(일반적으로 대금결제·공급 기록에 그 정도 보관 의무가 있다고 알려져 있으나 **확인 필요**). 함수 안 상수 `c_retention_years`.
2. **남은 엽전**: 제안 = 동의 시 소멸. 대안: 유상 충전분은 환불 대상으로 취급(청약철회·환불 규정과 연동). 환불정책이 정해져야 확정.
3. **최근 결제 건**: 결제 직후(예: 7일 이내) 탈퇴 시 환불 우선 안내 여부 — 법무 확인.
4. **재가입 제한**: 탈퇴 후 같은 이메일 재가입 허용 여부(현재 허용, 이전 기록은 복구되지 않음).
5. **본인 확인 강화**: 탈퇴 직전 비밀번호 재입력/최근 로그인 요구(현재 미구현; 구글 로그인 계정과의 정합 필요).
6. **데이터 열람·내보내기**(본인 요청 시 내 정보 내려받기) — 미구현, 필요 여부 결정.

## 4. 알려진 한계·위험
- **백업·복구 지점**: DB 백업(PITR 등)에 삭제 전 데이터가 일정 기간 남을 수 있다. 호스팅(Lovable Cloud/Supabase)의 보존 기간은 확인하지 못했다.
- **외부 처리자**: AI 해석을 OpenAI API 로 보내면 출생정보가 포함된다. 보관·학습 사용 여부와 삭제 요청 방식은 **미확인** — 연동 시 개인정보처리방침에 위탁·국외 이전으로 고지해야 하는지 확인 필요. 소셜 로그인(구글)·이메일 발송사도 동일.
- 서버 로그·오류 수집에 개인정보가 남지 않는지 점검 필요(현재 코드는 이름·생년월일을 로그로 내보내지 않도록 설계돼 있으나 전수 확인은 안 됨).
- 동시 요청(탈퇴 중 결제 승인 도착 등): 대기 주문 취소로 승인이 와도 충전되지 않음을 가상 DB 에서 확인했지만, 실제 동시성은 staging 확인 필요.
- 이 기능을 켜는 순서: ① 위 결정 승인 → ② 운영 SQL 적용(승인) → ③ staging 에서 실제 계정으로 탈퇴 E2E → ④ `ACCOUNT_DELETION_ENABLED=true`.

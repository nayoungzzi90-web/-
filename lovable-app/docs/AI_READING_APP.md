# AI 풀이 앱 연결 (2026-11-05, 2026-11-09 갱신) — 기본 꺼짐

기본 사주·심층 연애운·궁합을 **열람한 사람**이 풀이를 열면 서버가 (2026-11-09부터 버튼 없이 자동으로) 판단 카드(R-002~R-005) → GPT 작성 → 코드 자동 검수 → (설정 시) Gemini 독립 감수 → 저장 순서로 만든다.

## 화면 동작 (2026-11-09)
- **열람한 사람**: 풀이 화면을 열면 AI 풀이를 자동으로 만든다(`ReadingBlock` → `AiReading auto`). 만드는 동안 기다림 화면. 서버가 열람 권한·하루 한도·예산을 확인하고, 이미 만든 풀이는 저장본을 그대로 돌려준다.
- AI 풀이가 나오면 **그것을 주 풀이로** 보여 주고 전문용어가 많은 템플릿 풀이는 숨긴다(절입 시각 근처 출생 안내문은 따로 남김). 꺼짐·실패·한도 초과면 **기존 템플릿 풀이를 그대로** 보여 준다(빈 화면 방지).
- **열람 전**: 서버(`shapeSections`)가 전문용어가 든 무료 본문·제목줄·미리보기를 보내지 않는다. 쉬운 말인 앞 섹션만 무료로 열리고, 나머지는 잠금 카드(제목 + 쉬운 미리보기). 지금 템플릿은 첫 섹션이 거의 항상 전문용어를 담아서 기본사주·연애운은 무료 본문이 사실상 없다(제품 결정 필요: 무료 첫 섹션을 AI로 쓸지 등).
- 기본사주 화면 상단은 "나의 오행 친구"(캐릭터 + 기운 분포)로 쉬운 말 소개를 제공한다. 템플릿 섹션 제목 3곳도 쉬운 말로 바꿨다.
- 자동 생성이므로 AI 모드를 켜면 열람한 사용자가 화면을 열 때마다 서버를 부른다(새로 만들 때만 원가 발생, 하루 한도·예산 한도가 상한).

## 모드
| 모드 | 쓰는 명제 | 보여 주는 것 |
|---|---|---|
| off(기본) | — | "준비 중" 안내만 |
| trial | 전문가 승인 전 초안 포함 | 감수 차단(BLOCK)·실패만 숨기고, "시범 풀이(검수 전)" 표시와 함께 |
| live | 승인된 명제만 | 자동 검수 통과(READY) + Gemini 감수 통과(PASS)만. 감수 설정이 없으면 시작하지 않음 |

지금 모든 카드 문장이 초안이라 **live 로 켜면 풀이가 만들어지지 않는다**(승인된 명제가 없음). 켠다면 trial 부터다.

## 안전장치
- 열람 권한은 서버가 DB 에서 확인(`unlocked_readings`, 본인만). 4주는 두 엔진이 같을 때만.
- 같은 사람·같은 풀이·같은 버전은 한 번만 만든다. 재시도 3번, 5분 넘게 멈춘 작업만 다시 시작.
- 한 사람 하루 새 AI 풀이 3개(기본), 서비스 전체 하루 원가 상한(진행 중 작업은 예약 금액으로 미리 뺌), 풀이 1건 원가 상한, 킬 스위치.
- 모델·DB 에 고객 이름·출생정보 원문을 보내거나 저장하지 않는다(이름은 응답할 때만 넣음, 열람 id 는 해시).
- AI 코드·프롬프트·카드 문장은 서버 번들에만 있다(운영 빌드 검사 `reading-bundle.test.ts`).
- 설정이 하나라도 없거나 DB 함수가 없으면 시작하지 않는다.

## 궁합의 상대 정보 처리
- 상대도 두 엔진으로 4주를 이중 확인한다. 모델에는 두 사람의 계산 결과(카드 문장·사실 줄)만 보낸다.
- 본문은 상대를 "상대"라고만 부른다. 상대 이름·생년월일은 모델·DB(`ai_readings`)·응답 어디에도 들어가지 않는다(시험으로 확인). DB 에는 두 사람 출생정보의 해시인 열람 id 만 남는다.
- 상대가 자기 정보를 지워 달라고 할 때의 처리(열람 id 로는 상대를 찾을 수 없음)는 약관·개인정보 처리방침에서 정해야 한다 — 법무 확인 항목.

## 품질 측정 (2026-11-06~09, 실제 GPT 작성 + 실제 Gemini 감수, 기본 사주 30개 생년월일)
- 작성 모델 `gpt-5.4-mini`, 감수 `gemini-3.5-flash`. 감수 판정(PASS/REVIEW/BLOCK)은 코드가 정한다.
- 한 번 돌릴 때마다 PASS 약 22~25건, REVIEW 2~6건, BLOCK 0~3건, 작성 실패 0~2건(30건 기준). 같은 설정에서도 이만큼 흔들리므로 작은 규칙 변경의 효과는 구분되지 않는다.
- 비용은 풀이 1건 약 65~95원(작성 + 감수 합), 감수는 약 4~9원. 가격은 환경변수 값 기준이라 공식 가격 확인 필요.
- 심층 연애운 10건: PASS 8, REVIEW 1, BLOCK 1. 궁합 10건: PASS 7, REVIEW 3, BLOCK 0. 작성 실패 0.
- 반복되는 약점: 근거 없는 덧붙임(UNSUPPORTED), "볼 여지가 있다"를 단정으로 쓰는 과장(OVERSTATED), 명제 한계 누락. 실제 사실 오류(예: 오행 혼동)는 감수가 잡아냈다. 감수 자체도 가끔 틀린다(월간과 계절 기운 혼동).
- 모든 풀이가 `NEEDS_REVIEW`인 이유는 명제가 전문가 승인 전(DRAFT)이기 때문이다(코드 정상 동작).

# 풀이(3,000자 이상) 이식 — Lovable 앱에 규칙형 풀이 연결 (2026-10-29)

## 무엇을 했나
기본 사주·심층 연애운·궁합 화면의 얇은 문구를, 별도 프로젝트에서 만든 **규칙형 풀이 작성기**(준비된 문장을 사주 사실에 맞춰 조합, AI 아님)로 바꿨다.
- 기본 사주 3,000자 이상(실측 3,150~3,950), 심층 연애운 4,000자 이상(실측 4,000~4,330), 궁합 1,500자 이상(실측 1,530~1,640). 출생 시간을 몰라도 같은 기준을 채운다(시간 미상 안내 문단을 덧붙임; 시주를 지어내지 않는다).
- 글은 결정론적이다: 같은 입력이면 같은 글, 다른 사주면 다른 글.

## 구조
| 위치 | 역할 |
|---|---|
| `src/lib/reading-core/` | 상위 저장소(`../engine/manse`, `../src/lib/...`)의 **복사본**(32개 파일, 직접 수정 금지). 상대 경로 구조를 유지해 import 수정이 필요 없다. 갱신: `node scripts/sync-reading-core.mjs`, 검사: `--check` |
| `src/lib/reading.server.ts` | 서버 전용. 입력 검증 → 두 엔진으로 계산 → 4주 비교 → 풀이 작성 → 잠금 처리 |
| `src/lib/reading-fns.ts` | 서버 함수 `getReadingPreview`(공개, 요청 제한) · `getReadingFull`(로그인 필수, 열람 기록 확인) |
| `src/components/ReadingBlock.tsx`, `ReadingView.tsx` | 화면. 무료 섹션 + 잠금 목록 + 결제 안내 |

## 안전장치
1. **이중 엔진 확인**: 풀이를 쓰는 엔진(DE421 표)과 화면의 4주를 정하는 앱 엔진(astronomy-engine)이 **4주가 같을 때만** 풀이를 낸다. 다르면 풀이를 내지 않는다. 절입 시각 근처라 앱이 "검토 필요"로 표시한 경우에는 "출생 시각 확인" 안내로 구분한다.
   - 무작위 6,000개 입력(양력·음력·시간 미상 포함) 점검: 5,900건 정상, 31건 절입 경계 안내, 12건 미래 날짜 거부, **검증 불일치(경계 밖) 0건**.
   - 이는 두 구현의 일치이지 KASI 공식 확인이 아니다(`R001_RANGE_EXTENSION`, `KASI_API_GUIDE_NOTES` 참고).
2. **서버가 잠금을 집행**: 열람 권한이 없으면 잠긴 섹션의 **본문을 응답에 넣지 않는다**(제목과 36자 미리보기만). 열람 여부는 서버가 DB(`unlocked_readings`, RLS 본인만)에서 직접 확인하고, 조회 오류나 id 없음은 모두 잠금(fail-closed).
3. **번들 검사**: 풀이 문장·엔진 데이터는 서버 번들에만 있고 클라이언트 번들에는 없다 — 실제 운영 빌드를 만들어 확인하는 시험(`reading-bundle.test.ts`, 서버에는 있다는 대조군 포함).
4. **복사본 드리프트 검사**: 원본과 다르면 시험이 실패한다(`reading-sync.test.ts`).
5. 공개 미리보기에는 기존 요청 제한(R015)이 같은 관문(`rate-gate.server.ts`)으로 적용된다.

## 알려진 한계
- 이것은 **준비된 문장의 조합**이다. 같은 일간·십성 조합이면 문장이 겹칠 수 있다(다른 사주와 문단 40% 이상 다름을 시험으로 확인). AI 풀이는 비용 안전장치(`src/lib/report/budget.ts`) 아래에서 상위 상품으로 붙일 계획.
- 풀이 문장의 명리학적 타당성은 전문가 검수 전이다(`finalApproved=false`, 화면에 "시범 계산·검증 중" 표시 유지).
- 궁합은 상대 정보(양력/음력 입력)가 필요하며, 열람 id 는 `compat:<상대 입력 날짜>` 이다.
- 유료 열람 기능은 아직 꺼져 있다(DB 카탈로그 비활성, 결제 꺼짐). 지금은 무료 섹션만 보인다.
- 한글 조사(은/는, 이/가…)는 500개 사주×2상품에서 "한자(한글)+조사" 패턴 오류 0건을 확인했으나 모든 문장 조합을 전수 검사한 것은 아니다.

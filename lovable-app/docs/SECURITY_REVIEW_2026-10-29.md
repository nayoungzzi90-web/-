# 보안 검토 결과 (결제 켜기 전 점검)

독립 검토 1회 + 직접 점검. 고위험(무료 엽전/열람, 타인 정보 열람, 계정 탈취, XSS, 오픈 리다이렉트)은 발견되지 않았다. 아래는 남은 항목.

## 이번에 고친 것
- 궁합 열람 id(`compat:YYYY-MM-DD`)가 입력 검증에 막히던 문제.
- 로그인한 풀이 요청이 공용 IP 한도("unknown" 버킷)에 걸려 결제 회원까지 막힐 수 있던 문제.
- `PAYMENTS_MODE=sandbox` 가 production 에서도 동작하던 문제(production 에서는 무시, disabled).
- 가격표 SQL 이 신규 상품의 active 를 기본값에 의존하던 문제(명시적 false).

## 결제 켜기 전에 결정·수정해야 하는 것 (미수정)
1. **열람이 출생정보에 묶여 있지 않음.** `basic` 1회 결제로 `me` 를 바꿔가며 여러 사람 풀이를 받을 수 있다. 권장: 열람 id 에 정규화한 출생정보 해시를 포함하거나, 기본/연애운은 저장된 프로필에서 서버가 읽는다(SQL spend 형식도 함께 수정).
2. **초대 보상 환불 루프.** 보상이 첫 결제 즉시 지급되어, 초대받은 쪽이 환불해도 초대한 쪽이 이미 쓴 엽전은 회수되지 않는다. 같은 사람이 두 계정을 쓰면 50% 할인과 같다. 권장: 환불 가능 기간이 끝난 뒤 지급(보류), 회수 불가 시 마이너스 잔액/사용 제한, 기기·결제수단 한도.
3. **개인정보·약관 동의 증빙.** 동의 버전을 클라이언트가 보낸 값 그대로 저장한다. 허용 목록 검증 + `draft-` 버전에서는 실결제 차단 필요.
4. **탈퇴 후 남은 로그인 토큰.** 탈퇴 직후 만료 전 토큰으로 지갑/초대코드 행이 재생성될 수 있다. 민감 함수에서 사용자 존재 확인 필요. 탈퇴 후 도착한 결제의 환불 절차, 탈퇴 시 재인증도 정책 결정 필요.
5. **환불 기간 규칙.** `refund_purchase` 는 사용 여부만 본다. 환불 기간 정책 확정 후 기간 검사를 추가.
6. **배포 설정.** `TRUSTED_CLIENT_IP_HEADER` 를 프록시가 덮어쓰도록 설정하고 원본 서버 직접 접근 차단. 비로그인 미리보기 한도는 이 설정이 없으면 전체 공용 10회/분.
7. **보안 헤더(CSP, X-Frame-Options 등)가 설정돼 있지 않음.** 배포 환경(호스팅)에서 설정 필요.
8. **의존성.** `zod` 3.25.x 에 고위험 권고(GHSA-mrhx-c7xc-m3w5, 대용량 배열 검증 시 메모리 소모). 이 앱의 입력 스키마에는 배열이 없어 현재 노출은 낮다. 업그레이드는 메이저 변경이라 별도 작업. lockfile 이 없어(`bun.lock` 사용) npm audit 는 임시 lockfile 로 수행.

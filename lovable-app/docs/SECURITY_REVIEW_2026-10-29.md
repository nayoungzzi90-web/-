# 보안 검토 결과 (결제 켜기 전 점검)

독립 검토 1회 + 직접 점검. 고위험(무료 엽전/열람, 타인 정보 열람, 계정 탈취, XSS, 오픈 리다이렉트)은 발견되지 않았다. 아래는 남은 항목.

## 이번에 고친 것
- 궁합 열람 id(`compat:YYYY-MM-DD`)가 입력 검증에 막히던 문제.
- 로그인한 풀이 요청이 공용 IP 한도("unknown" 버킷)에 걸려 결제 회원까지 막힐 수 있던 문제.
- `PAYMENTS_MODE=sandbox` 가 production 에서도 동작하던 문제(production 에서는 무시, disabled).
- 가격표 SQL 이 신규 상품의 active 를 기본값에 의존하던 문제(명시적 false).

## 같은 날 이어서 고친 것 (사용자 승인: "추천대로 다 고쳐줘")
- **열람을 출생정보에 묶음.** 열람 id = `상품:출생정보 해시14자리`(`unlock-id.ts`). 한 번 결제로 다른 사람 풀이가 열리지 않는다. SQL `spend_coins` 도 같은 형식만 허용(옛 `basic` 형식 거부). 기존 운영 열람 기록이 있다면 옛 id 라 새 형식으로는 다시 열어야 한다 — 적용 전 현황 확인 필요.
- **초대 보상을 보류 지급으로 변경.** 첫 결제는 `held` 로만 표시, 7일 환불 기간이 지나도 환불 안 된 건만 `release_referral_rewards()`(서버 전용, 스케줄러가 호출)가 지급. 보류 중 환불은 보상 취소. 환불 반복으로 무료 열람이 나오는 경로가 닫힘.
- **자동 환불 7일 제한**(`REFUND_WINDOW_PASSED`). 7일은 제안값이며 약관·청약철회 고지와 맞춰 확정해야 한다.
- **탈퇴한 계정의 토큰**으로 지갑·초대코드가 다시 생기지 않도록 `ensure_user_setup` 이 auth.users 존재를 확인(`USER_NOT_FOUND`).
- **약관 동의 증빙.** 동의 버전이 현재 약관 버전과 같아야 주문 생성, 초안(`draft-`) 약관이면 live 결제 차단.
- **보안 헤더**(nosniff, referrer-policy, permissions-policy, HSTS) 서버 응답에 추가. CSP·X-Frame-Options 는 배포 환경에서 시험 후 도입.
- 시험: 보류·취소·7일·중복 지급·탈퇴 토큰·열람 id 형식(변조) 등 PGlite 변이 시험 추가.

## 아직 남은 것 (정책·운영 결정 필요)
1. `release_referral_rewards()` 를 주기적으로 호출할 스케줄러(Supabase cron 또는 서버 작업) — 적용 시 설정.
2. 탈퇴 후 도착한 결제 대사/환불 절차, 탈퇴 시 재인증 여부.
3. 환불 기간(7일)·보관 기간 등 법무 확정.
4. 배포 설정: `TRUSTED_CLIENT_IP_HEADER` 를 프록시가 덮어쓰도록, 원본 서버 직접 접근 차단. 설정이 없으면 비로그인 미리보기는 전체 공용 10회/분.
5. CSP / X-Frame-Options 도입(스테이징 시험).
6. `zod` 3.25.x 고위험 권고(GHSA-mrhx-c7xc-m3w5, 대용량 배열 검증 시 메모리). 이 앱 입력에 배열이 없어 노출 낮음; 4.x 업그레이드는 별도 작업.
7. 동시 요청(행 잠금) 검증은 PGlite 로 불가 → 스테이징 필수.
